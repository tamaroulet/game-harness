# 目的と終わりの条件（purpose）

## 大目的

ゲームを人間が作ることではなく、**開発基盤そのものが自分を改善しながら自走する工廠**を作ること。
人間は方針を出し、PR を非同期に承認するだけ。正しさは LLM の感想ではなく、決定論的な検査（終了コード・テスト・不変条件）が決める。
- 総監督が採用した定義（責任は総監督。D-018）。人間の定常作業は PR の非同期の承認だけ：`docs/design/foundation_v3_review.md:65`

## Goal までの距離（能力の段。2026-10-10 の総監督の判定）

| 段 | 能力 | 判定 | 根拠 |
|---|---|---|---|
| C1 | What 1 件を人間なしに統合ブランチへ積む | 達成 | `report.md:24`（済み 40）、`:27`（未収束 2） |
| C2 | What を人間との対話なしに生成する | 未達 | 計画役は未実行（`docs/progress.yaml:668-673`） |
| C3 | 工廠が自分の性能を数値で知る（北極星） | 一部 | 試行・ターン・トークンのみ（`report.md:24`）。北極星は無い（G0-5） |
| C4 | 計測に基づき、工廠が自分の改善 What を発案する | 未達・証拠なし | 改善 What はすべて人間との対話から生まれている |
| C5 | 外部ドメイン（3D 物理）で C1〜C4 が成り立つ | 未着手 | Phase 4（`docs/progress.yaml:686-`） |

H0 はどの段も進めない。C2〜C4 を設計するための観測を直す前提工事である。

## 原則（3 つ）

1. 思考する LLM は 1 か所。判定は機械（Git・unittest・不変条件のコード）
2. 会話は使い捨て。状態は Git・`queue.json`・ファイルにだけ置く
3. 測定器が先、作り込みは後。計器の数値を引用できない機能の What は起草しない（`notes/lessons-pending.md` → `docs/director/lessons.md` L-04）

## 試験台

3D 物理（MuJoCo）のベンチマーク環境。目的は工廠の能力の測定であって、ゲームの完成ではない。
物理は「浮動小数・積分・接触」を持つので、文字列処理より判定が難しい。だから測定器（不変条件オラクル・許容誤差テスト）を先に揃える。
- 注意：MuJoCo は同じビルド・同じ入力なら決定論的（decisions.md D-012）

## H0 の合格条件（機械判定）

操縦士が何も貼らない新しい総監督セッションで、総監督が report.md・handoff・この索引だけを読んで次に答え、実測と一致すれば合格。
1. `origin/main` の HEAD（`git rev-parse origin/main` と照合）
2. 最新 CI の合否（`gh` と照合）
3. 現在タスク（`docs/progress.yaml` の `active_task_id`）
4. キューの件数（済み・待ち・未収束・凍結）
5. mujoco の版
6. 操縦士が事前に用意した大局観の問い（答えは invariants.md・lessons.md から一意に決まるもの）
