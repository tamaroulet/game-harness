## 2. 意図

**方向（操縦士、2026-10-24）**

1. 適切に検索できる土壌を作る
2. 大局観を持ったプロジェクトの進め方を考え直す

この 2 つができれば、あとは直しながら進められる。

**進め方の原則**

- **ゴールの木**：最終ゴールから、深さの決まっていない木で分ける。節は、目的・届いた状態・仮定を持つ。最初は決め打ちで仮の木を作り、外の情報と評価で直していく。仮に置いた節には印を付ける
- **確実なものと仮説を分ける**：実行するタスクと、確かめる仮説を分けて持つ。仮説も木の節にし、確かめたら木に返す
- **評価**：事前（子の節で親に届くか）と事後（届いたか）の評価は、状態を持たない別の AI がする。進みは数ではなく評価で判じる。数は、無駄が無いかを評価するときの証拠に限る
- **改善と実装を分ける**：改善（木を直す）は議論と評価の場でだけ行う。実装は、木のタスクを 1 つずつこなすだけにする
- **作業の実行**：状態を持たない別の起動で、1 つずつ行う。台帳（DAG）に載せることと、誰が実行するかは別
- **外の知識**：問い → 収集 → 出典の照合 → 当てはめと暫定の案 → 評価者の批評 → 操縦士の確認 → 溜める、の流れで行う。問いは、方向と現状の資料を添え、仮説と確かめの聞き方を入れずに書き、投げる前に操縦士に見せる
- **無駄が無いこと**：トークン・人の待ち時間・AI の作業時間に無駄が無いことも、ゴールに含める
