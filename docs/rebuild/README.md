## 0.5 責務の 4 集約（独自用語の役職ごっこ全廃）

従来の 8 つの役職（総監督、計画役、分解役、監修役、実行役、調べ役、評価役、会話の席）を全廃し、責務を以下の 4 つに集約する（ステートレス起動）。

1. **プランナー（Planner）**: 要件と受入テストを定義する。
   - 最終目的と要件の側：総監督（受信箱 `C:\src\.local\inbox` 常駐）
   - タスクと受入テストの側：既存 planner。調べ役は役にせずプランナーの道具とする
2. **ワーカー（Worker）**: 要件を満たす実装コードを作成する（実行役および副操縦士実務）。受入テストファイルの変更は禁止
3. **レビュアー（Reviewer）**: 独立に検証・監査する（別系統モデル Argon および CI の静的・動的検査）
4. **人間（Maintainer）**: 最終責任と方針決定、高リスク変更の承認（操縦士）

## 2. 語彙の全面修正対照表（独自用語の全廃）

形式的な器（箱・段・門）を廃止し、ソフトウェア工学の標準的・実質的語彙へ統一する。

| 廃止する独自用語 | 引き起こしていた弊害・欺瞞 | 置換後の標準語彙 | 概念の転換（形式から実質へ） |
|:--|:---|:--|:---|
| **大ゴール / 中ゴール / 小ゴール**<br>（What、横木） | 階層の深さが固定され、中間階層を埋める作文タスクが発生。 | **最終目的（Objective）**<br>**要件（Requirement）**<br>**タスク（Task）** | 固定階層を持たない単純な DAG（有向非巡回グラフ）とし、末端の実行単位を「タスク」、達成状態を「要件」とする。 |
| **セクター（Sector 0〜6）**<br>**段（Stage 1〜6）** | 機能（空間）と順序（時間）を混同し、無駄の除去が後回しになる等の硬直化を招く。 | **対象モジュール（Module）**<br>**前提条件（`depends_on`）** | 人工的なフェーズ分けを全廃。前提条件が満たされたタスクは段数に関係なく即座に着手可能とする。 |
| **門（Gate 1〜3 / 局所・中・全体門）**<br>**防壁（Barrier 1〜3）** | 単体テスト 1 本の合否を門・防壁と呼び、セキュリティ機構があるかのように錯覚させる。 | **単体テスト**<br>**結合テスト**<br>**耐久テスト**<br>**静的解析（Lint/型）**<br>**ファイル権限・ブランチ保護** | 具体的な技術名称で呼ぶ。「防壁①」ではなく「ファイルアクセス権（ACL）」や「コマンド拒否リスト」と明記。 |
| **オラクル（Oracle）**<br>`oracle: { from: self }` | 実装者が自分で書いた甘いテストをオラクルと呼び、自己採点を正当化。 | **検証テスト（Verification Test）**<br>属性：`自己作成` / `独立作成` | 単なるテストをオラクルと呼ばない。誰が書いたかを明示し、自己作成テストのみのタスクは「独立検証なし」と識別。 |
| **工廠 / H ライン / ゲームのライン** | 対象リポジトリやパイプラインの違いを比喩で呼び、実体を曖昧にする。 | **ゲーム生成パイプライン**<br>**ハーネス改修パイプライン** | 対象を平易な日本語またはディレクトリ名（`bench/`, `harness/`）で直接指す。※既存の識別子は一括置換せず順次移行。 |
| **物差し / 外側の周期** | 通常のベンチマークや回帰テストを特殊用語で呼び、統計的検証を鈍らせる。 | **ベンチマーク（Benchmark）**<br>**回帰ベンチマーク実行** | 測定感度やサンプル数（N）を問う通常のベンチマークとして扱う。 |
| **走らせ役 / 探針 / カナリア** | 実体が Git 管理外のスクリプトや死蔵テストであることを隠す。 | **常駐ワーカー（Runner）**<br>**集計スクリプト**<br>**スモークテスト** | 通常のソフトウェア部品として Git 管理・テスト対象に組み込む。 |

## 3. 人間と AI の実効的な協調インターフェース

### 3.1 リスク 3 層別
- **低リスク（Tier 0）**: ドキュメント、死蔵コード削除、非保護領域の軽微な修正。手順 5 までは人間の 1 分確認を通し、手順 5（ブランチ保護）完了後に自動マージへ移行。
- **中リスク（Tier 1）**: 通常の機能モジュール追加・修正。「テスト先行・分離」を満たし、独立レビュアー（別系統モデル）の差分監査通過で自動マージまたは事後確認。
- **高リスク（Tier 2）**: CI ワークフロー、合否判定スクリプト、常駐ワーカー、権限設定、既存テスト変更。**他タスクとの束ねを機械的に禁止**し、人間向けに 5 行の客観事実（変更理由、高リスク理由、検証の出所、副作用、独立モデルの批評）のみを提示して 1 分で判断させる。

### 3.2 形式主義の物理的排除
- **テスト先行・分離の原則**: プランナーが失敗する受入テストコードを先に定義し、ワーカー実行時はテストファイルを変更禁止（読み取り専用）として自己採点（`from: self`）を物理排除する。
- **配線検証（Wiring Check）の義務化**: 単体テストだけでなく、「システムのエントリーポイントから機能が呼び出されていること（import グラフの到達性）」を完了条件に含める（D20 根絶）。
- **仮説の管理**: 新しい番号体系（A, P, X 等）は新設せず、要件属性に「検証の状態」（`検証済み` / `自己検証のみ` / `仮説`）を持たせることで単一の DAG に統合する。
