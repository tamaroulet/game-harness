# 練習の課題 P2：倉庫の在庫（stock）

計画役と監修のループの確定の率を測るための練習の課題（D-106 §7.3）。ベンチの 10 本には入らず、採点もしない。物理の無い課題を 1 本入れ、計画役が物理の課題だけに合った分け方を覚えないかを見る。

## 模型

- 倉庫：品目ごとの在庫の数（0 以上の整数）を持つ。始めはどの品目も 0
- 倉庫は 10 個（番号 0〜9）。操作の対象は「今の倉庫」で、始めは 0 番
- 操作：文字列の行の list。各行は次のどれか。品目は英小文字と数字の 1〜16 文字、数は 1 以上 10000 以下の整数、倉庫の番号は 0 以上 9 以下の整数
  - `use <倉庫の番号>`：今の倉庫を替える
  - `in <品目> <数>`：今の倉庫に入れる
  - `out <品目> <数>`：今の倉庫から出す
  - `move <品目> <数> <倉庫の番号>`：今の倉庫から、その番号の倉庫へ移す（今の倉庫と同じ番号は形の合わない行とする）。今の倉庫は替わらない

## 要件

- REQ-01：公開の入口。リポジトリの根の `stock` パッケージは、関数 `apply(lines)` と `report(state)` を持つ。`apply` は、すべての倉庫が空の状態から `lines` を順に当て、状態（倉庫の番号から、品目から数への辞書への辞書）を返す。`report` は、状態から、品目ごとの全倉庫の合計を、品目の文字の順に `<品目> <数>` の行の list で返す
- REQ-02：行の形。形の合わない行・範囲の外の数・番号には `ValueError` を投げ、その行の番号（1 から数える）を例外の文に含める
- REQ-03：在庫は負にならない。`out` と `move` で、その倉庫の在庫より多くを出そうとした行には `ValueError` を投げ、それより前の行までの状態は返さない（`apply` は全部か無しか）
- REQ-04：保存。`move` は全倉庫の合計を変えない。`in` は合計をその数だけ増やし、`out` は減らす
- REQ-05：順に依らない合計。`in` の行だけからなる `lines` は、行の順を入れ替えても、`report` の結果が同じ
- REQ-06：決定論。同じ `lines` で 2 回呼ぶと、同じ状態を返す
