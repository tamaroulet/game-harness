# 課題 B09：受け止め（catcher）

段 3 のベンチマークの課題。工廠には、この全文と判定役（`tests/catcher_judge.py`）の検証コマンドだけを渡す。

## 模型

- 場：x 軸の上の区間 [−0.5, 0.5]（m）。鉛直の上向きを +z とする。受け止めの線は z ＝ 0
- パドル：幅 0.2 m（中心 p から ±0.1）。始めは p ＝ 0。各歩で、操作の速さ v（m/s）を [−1, 1] に切り詰め、p ← p ＋ 0.002·v とし、p を [−0.5, 0.5] に切り詰める
- 玉：10 個（0 番から 9 番）。i 番の玉の x は、x_i ＝ −0.4 ＋ 0.8·u_i。u_i は Python の `random.Random(seed)` から `random()` を 10 回呼んだ i＋1 回目の値。i 番の玉は、1 歩目から 375·i 歩目まで高さ 1.0 に止まって保たれ、375·i ＋ 1 歩目から重力（−9.81 m/s²）で自由に落ちる（空気の抵抗なし。x は変わらない）。玉どうし・玉とパドルの接触は無い
- 時間の刻み 0.002 s。玉の落下は MuJoCo 3.15.0（`mujoco` パッケージ）の既定の積分（Euler）で計算する。落ち始めて j 歩目の後の玉の高さは z ＝ 1 − 9.81·0.002²·j·(j＋1)/2、速さは vz ＝ −9.81·0.002·j
- 判定：i 番の玉は、z が初めて 0 未満になった歩（375·i ＋ 226 歩目）に、一度だけ判定される。その歩の後のパドルの中心 p について |x_i − p| ≤ 0.1 なら「受けた」、そうでなければ「落とした」。判定の後も玉は落ち続けるが、二度は判定されない

操作：`controller(state)` は、k 歩目の前に 1 回呼ばれ、その歩の操作の速さ v を返す。`state` は k − 1 歩目の後の状態の写しの辞書：
- `step`：済んだ歩の数 k − 1（int）
- `paddle`：パドルの中心 p（float）
- `balls`：長さ 10 の list。i 番目は `x`（float）・`z`（float）・`vz`（float）・`resolved`（判定が済んだか、bool）・`caught`（判定が済んでいれば受けたか（bool）、済んでいなければ `None`）を持つ辞書

## 要件

- REQ-01：公開の入口。リポジトリの根の `catcher` パッケージは、次の 2 つの関数を持つ。
  - `play(seed, controller, steps)` は、始めの状態から `steps` 歩進め、辞書を返す：`caught`（受けた数、int）・`missed`（落とした数、int）・`events`（判定の list。判定の順に、`ball`（玉の番号、int）・`step`（判定された歩、int）・`caught`（bool）を持つ辞書）・`paddle`（長さ `steps` の list。k 番目は k＋1 歩目の後の p、float）
  - `auto_play(state)` は、`controller` として使える関数で、操作の速さを返す
- REQ-02：入力の範囲。`seed` は 0 以上 2³² 未満の整数、`steps` は 1 以上 5000 以下の整数、`controller` は呼び出せるもの。外れた値・整数でない値（`bool` を含む）・呼び出せない `controller` には `ValueError` を投げる。`controller` が有限の数でない値（`bool`・`None`・NaN・無限大を含む）を返したら、`play` は `ValueError` を投げる
- REQ-03：決定論。同じ `seed` と、同じ状態に同じ値を返す `controller` で 2 回呼ぶと、返り値は、すべての値がビット単位で一致する
- REQ-04：玉の置き場。どの呼び出しでも、`state["balls"][i]["x"]` は x_i と一致する（差 1e-12 以下）
- REQ-05：落下。`state` の各玉の `z`・`vz` は、止まって保たれる間は 1.0 と 0.0、落ち始めて j 歩目の後は模型の式の値と 1e-9 以内で一致する
- REQ-06：一度だけの判定。`events` は、`steps` 歩までに判定の歩が来た玉のすべてを、ちょうど一度ずつ、判定の歩の順に持つ。各玉の判定の歩は 375·i ＋ 226 で、`caught` は模型の判定と一致する。`caught` ＋ `missed` は `events` の長さで、`caught` は `caught` が真の事象の数。`state` の `resolved`・`caught` は、判定の歩の後の呼び出しから、その判定を表す
- REQ-07：パドル。`paddle` の各値は、`controller` が返した値から模型の式で計算した p と 1e-12 以内で一致する（切り詰めを含む）
- REQ-08：写し。`controller` が受け取った `state` を書き換えても、その後の進み方は変わらない
- REQ-09：自動の操作。どの `seed` でも、`play(seed, auto_play, 3700)` の `caught` は 9 以上（10 個の玉の判定の歩は 3601 歩目までに来る。どの 2 つの判定のあいだも 375 歩あり、その間にパドルは 0.75 m 動ける）
