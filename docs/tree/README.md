# 目的・要件・タスクの木（docs/tree/tree.yaml）

## 1. 形

- 節は 2 種類：`objective`（最終目的。1 つ）と `requirement`（要件：満たされたかを確かめられる状態）
- 前提関係は、要件どうしの `depends_on` だけで持つ。「X が Y に依る」は、「Y が満たされないと X は満たされない」ということ。階層の深さは決めない。循環は作らない
- タスクは、要件の `tasks` に台帳の ID を 1 か所だけ書く。タスクの題・受入・検証のコマンド・タスクどうしの順は、台帳が正本
- 台帳に無いタスクの案は、要件の `proposals` に文で書く。台帳に入ったら `tasks` に移す

## 2. 要件の欄

| 欄 | 意味 |
|:--|:--|
| `achieved_when` | 満たされた状態。記録で確かめられる事実の形で書く |
| `verify_by` | 確かめ方。`test:independent`（ワーカー以外が書いた検証テスト・CI の検査）・`reviewer`（レビュアーが記録を読んで判じる）・`human`（操縦士が判じる） |
| `status` | `未達`・`仮説`（成り立つと見ているが確かめていない主張）・`自己検証のみ`（作った者のテストか報告だけで済みになった）・`検証済み` |
| `tasks` / `proposals` | 付くタスク（台帳の ID）と、台帳に無い案 |
| `evidence` | 今の状態の根拠。総監督が自分で確かめていないものには「未確認」と書く |
