# 箱（実装役・門・採点）の用意と確かめ

実装役が書いたコードは、WSL2 の Docker の箱の中だけで走らせます（v3 §8 の E4）。回す側は Windows のままで、箱とのやり取りは標準入出力の tar だけです。
部品は `harness/box.py`・`harness/box_tree.py`・`box/`・`config/box.json` です。

## 用意（1 回だけ。やり直せる）

作業ディレクトリはリポジトリの根です。

```
python -m harness.box setup
wsl --terminate Ubuntu
python -m harness.box build
```

- `setup` は WSL2 の中を root で整えます：bench 利用者（uid 1000、docker の組に入れない）、agy（`config/box.json` の版、root の持ち物の置き場）、Docker Engine、`/etc/wsl.conf`（Windows のフォルダと実行ファイルを見えなくする）。
- `/etc/wsl.conf` は `wsl --terminate` の後に効きます。効いた後は、WSL2 から `/mnt/c` は見えません。Windows から `wsl.exe` で呼ぶ向きは動きます。
- `build` は像を 2 つ造ります（箱と中継）。`box/` か `config/box.json` の agy の値を変えたら、造り直します。造り直さないと、走りの前の確かめで止まります。

## ログイン（人の作業）

agy の認証は WSL2 の bench 利用者が持ちます。定額の方を選びます（Pay As You Go は選ばない）。

```
wsl -d Ubuntu -u bench --cd /home/bench -- bash -lc "agy"
```

Google のサインインが済んだら `/quit` か Ctrl+C で抜けます。

## 確かめ（利用枠を使わない）

```
python -m harness.box check
```

合格と出れば、次のことを確かめています。

- 像が今の `box/` と設定から造られた。
- 箱の利用者は bench で、ルートは読み取り専用で、`/mnt` は空で、WSL の部品が見えない。
- 直の接続が届かず、名前の解決もできない。
- 実装役の箱で agy の認証が読め、試験の箱には認証が無い。
- 中継が、許した宛先を通し、許していない宛先を拒む。

## 箱の決まり

| 箱 | 入れるもの | ネット | 外へ返すもの |
|:--|:--|:--|:--|
| 実装役 | 作業の木の写し（`.git` を除く）、agy の認証 | 中継だけ（`box/proxy/allow`） | 変更したファイル |
| 門 | 作業の木の写し | なし | 試験の出力 |
| 採点 | 段の木の写し、隠しテスト | なし | 結果の 1 行 |

- どの箱も 1 回ごとに使い捨てです。ホームと `/tmp` は tmpfs で、実装役の作業の木は名の無いボリュームです（容器と一緒に消えます）。
- 実装役の箱には使い捨ての git があります（開始の木を 1 コミット）。外の本当の `.git` は見せません。
- 受け取らないもの：`.git` の下、リンク、特殊なファイル、木の外を指す名前、Windows で作れない名前、大文字と小文字だけが違う 2 つ目、大きすぎるファイル、課題のパッケージと試験の外に新しく作ったファイル。

## 分かっている限界

- 実装役のコードは採点の箱の中で隠しテストと同じプロセスで走るので、結果の行を偽れます。敵対的な実装役は想定していません。
- 実装役は箱の中で自分の agy の認証を読めます。出せる宛先は中継で絞っています。
- WSL2 の root は、Windows のドライブをマウントできます（`automount` を切っても、root なら戻せる）。箱は権限を落としているので届きません。Docker の操作は root だけです。

## 走りの通し方

`stage --box` の印があるタグは、run・finish・bench_pair が印に従って箱で走ります。今の Windows の基準のタグは、印が無いのでそのまま採点し直せます。

```
python -m harness.bench_chain stage --tag <t> --set dev --bases B07,B08,B09 --box
python -m harness.bench_chain run --tag <t> --repo <クローン> --base <rev> --staged <stage が出した置き場> --out <置き場> --implementer config/bench_implementer_agy.json
python -m harness.bench_chain finish --tag <t> --repo <クローン> --out <置き場>
```

- 走りは操縦士のアカウントで回します。実装役が書いたコードは箱の外で走りません（実装役・門・積む前の全件・進捗の記録の検証・採点の 5 か所）。
- 実装役はコマンドを使えます（`--sandbox` は付けません。1.5.3 の `--sandbox` はコマンドを止めないので、コマンド無しの走りは作りません）。
- 新しく作ったファイルのうち、課題のパッケージと `tests/test_<パッケージ>*` の外のものは受け取りません。受け取らなかった名は試行の記録（`box_dropped`）に残り、門に落ちたときは次の試行の入力で実装役に知らせます。
- agy の `--print-timeout` は、stream-json の入力では終了コード 0 のまま、標準エラーの `AGY_ERROR` の `reason` が `print_timeout` になります。時間切れとして扱います。
- 呼び出しが途中で切れたとき（agy の result が ERROR で error が `interrupted`。終了コード 1、応答は空）は、環境の異常として扱います。A は段を無効（REQ-22）にして走り直し、B は What を呼び直します。11-12 に、箱の Docker のつまずきと同じ時に 1 回起きました（v3 §15 の 11-12）。
- 箱の確かめ一式（像・網・箱の中の見え方・中継）は、run の起動ごとに最初の段だけ走らせます（1 回 8〜10 秒、ほとんどが中継の確かめ）。段ごとには像の指紋を見て、実装役の呼び出しごとに中継の像と動きを見ます。確かめに外れたときは覚えず、次の段でもう一度確かめます。
- ベンチの走行の H ラインは、受信箱の報告（report.md・TODO.md）を書きません（走行では誰も読まず、目的までの距離の節が poll ごとに 40 秒前後かかっていた。v3 §15 の 11-12 その 2）。

## 素のエージェント A の走り（v3 §8 の E5）

stage と finish は B と同じです。run だけを `harness.bench_solo` に替えます。A は箱でだけ走るので、stage に `--box` が要ります。

```
python -m harness.bench_solo run --tag <t> --repo <クローン> --base <rev> --staged <stage が出した置き場> --out <置き場> --implementer config/bench_implementer_agy.json
```

- 段ごとに実装役を新しく 1 回だけ呼びます。呼び出しの時間は B の段の上限と同じ 1 時間で、門・やり直し・受け取らなかった知らせはありません。頼みは `docs/bench/prompts/solo.md` の前置きに、B と同じ What の文と検証コマンドを足したものです。
- 段の開始のコミット・箱・実装役の設定・呼び出しの経路・受け取りの決まり・試行の後のコミット・記録の形は B と同じで、finish がそのまま採点します。鎖の記録と公開の集計には `arm: solo` が載ります。タグは腕ごとに分けます。
- 走り直しは環境の破れだけです。利用枠が尽きたら、その段を無効と書いて終了コード 2 で止まります。回復の後に同じ命令で続きから走ります（書き終えた土台と走りは使います）。

### 会話の形（`--chat`、腕の名は chat。v3 §15 の 11-12 その 2）

素直なチャットの使い方に合わせ、鎖ごとに 1 つの会話を続けます。run に `--chat` を足します（stage と finish は同じ）。

- 1 段目は今の A と同じ頼みで新しい会話を始め、2 段目からは前置きを外した「次の頼み」を同じ会話に送ります（agy の `--conversation`）。走り直しは「同じ頼みの送り直し」と書いて、同じ会話に送ります。作業の木は、どの段も前の段の先端と新しい仕様から始めます（今の A と同じ）。
- 会話の記録は、鎖ごとの名前つきボリューム（`box-chat-<タグ>-<土台>`）を実装役の箱のホームにして残します（今の A と B のホームは、1 回ごとに使い捨ての tmpfs）。認証は呼び出しの間だけホームに置き、実装役が終われば消します。時間切れで止めた箱では残るので、鎖を書き終えたらボリュームごと消します。利用枠や異常で途中で止まったときは、続きから走るために残します。
- 会話の ID は段ごとの run.json（`conversation`）と鎖の記録に書きます。続きから走るときは、書き終えた段の run.json から引きます。

## A と B の比べの集計（v3 §15 の 11-08 その 4 の決め 5・6）

finish は、段の行に走りの記録から数えた `cost`（トークンの内訳とキャッシュでない分 `non_cache`・実時間・利用枠の待ち・エージェントの時間・手番・コマンド・受け取らなかったファイル。走り直しの試しも足す）と、B だけ `gate`（門を通ったか・1 回目で通ったか・試行の数・延長・全件で落ちた試行）を足します。A と B の走りのタグを並べて集計します（利用枠は使いません）。

```
python -m harness.chain_compare --a <A の公開の集計の置き場> [...] --b <B の公開の集計の置き場> [...] --json <書き先>
```

- 置き場は、開発の組なら `<クローン>/bench/records/chains/<tag>`、保留と取っておく組なら非公開の oracles の `chains/runs/<tag>`（公開には合計しか無い）です。
- 主は累積の完了（段 k で、段 0〜k の有効な隠しテストが全部通る。今までの「通ったステージ」は、前の段で通っていた試験だけを分母にしていた）と、段あたりのキャッシュでない分の差（B − A）です。4 分割表・土台ごとの表・「腕に違いが無い」を帰無にした符号の入れ替えの検定・Holm・散布図の数・副の物差しを出します。判定の手順と非劣性の検定の方法は規約で決めます（この部品は数を出すだけ）。
- A の段の行の `stop` が `tokens` なのは、B の段の予算（300 万トークン）を超えた印です。A の呼び出しはトークンでは切らないので、集計は A の止まり（上限の切れ）を時間切れだけで数え、予算を超えて自分で終えた段は「終えたと言った段」に数えます。
