# V2-6：前提を狙う抽出（Targeted State Sampling）と T2 の固定の性質

- 状態: 実装済み。v2-smoke-04 の前
- 前提: game-harness#93（T2 の固定の性質は、T2 だけを正しく実装しても 33 系列で 0.75 の確率で VACUOUS）
- 裁定（2026-09-25、オーナー）:
  1. T2 は直す。ただし特定の操作列（「何もしない手を N 回」）を宣言に書く構文ではなく、**生成器の抽象**（開始状態の領域からの抽出＋入力の分布）として実装する
  2. T1 の対策（base の振る舞いを T0 の性質にする）は**見送り**。形式化した性質（ホワイトボックスの契約）と、形式化していない暗黙の仕様を守る P2P（ブラックボックスの防壁）の役割分担を保つ
  3. v2-smoke-04（N=1）を挟んでから本走
- 原則（Phase 4 を見据えて）: 希薄な前提（衝突・関節の限界・転倒・把持・固定）は、アドホックな操作列ではなく、「目標とする状態の領域から開始状態を抽出するサンプラー」で起こす。系の破綻は大域の不変条件（保存則・非貫通など）と P2P の門で捕まえ、細かな性質を増やしすぎない

## 1. 抽出の宣言（`sampling`）

性質の宣言に任意のキー `sampling` を置ける。

| キー | 意味 |
|:--|:--|
| `start`（必須） | 開始状態の領域。開始状態だけで評価できる式（before の Phase・ActiveMino と、after を使わない関数）。開始状態の生成器から拒否抽出で絞る |
| `quiet` | 開始から何手、入力の分布を変えるか。整数か `{"param": "PR-xx", "add": n}`（構造化仕様から引く。数値を書き写さない） |
| `rate` | その区間で各キーを押す確率（0〜1）。0 なら無入力、小さければ低頻度 |
| `count` | 足す系列の本数（1〜10、既定 3） |

- 操作列は書かない。区間の後は、ほかの系列と同じ乱数の手に戻る。系列は、公開・非公開のシードの系列に**足す**もので、置き換えない
- 抽出は実装を使わない（開始状態の材料と参照モデルだけ）。領域に入る開始状態が見つからなければ `PROPERTY_UNSATISFIABLE`（宣言か生成器の欠陥。実装に依らない）
- game-harness#88 の Directed（given から取り出す開始状態の前提と最初の手）はそのまま。`sampling` はその上に足す一般化で、Directed は `quiet = 0` の特別な場合になった
- Phase 4 への写し方：`start` は「接触の近傍」「関節の限界の近く」などの状態空間の領域、`quiet`・`rate` は「外力を弱める・入力を止める区間」。同じ形で書ける

## 2. T2 への宣言

P-T2-02・03・04（前提は「このティックで固定が起きた」）に：

```json
"sampling": {"start": "before.ActiveMino != null && !fits(moved(before.ActiveMino, 0, -1))",
             "quiet": {"param": "PR-03", "add": 1}, "rate": 0, "count": 3}
```

- 接地した開始状態から、ロック猶予（PR-03 = 30）＋1 手のあいだ入力を止める。正しい T2 の実装なら、その区間で必ず固定が起きる。起きなければ反例の 1 行が出る（VACUOUS の手探りにならない）
- **`rate` を 0 にした理由**（`experiments/v2/tools/quiet_mc.py`、近似）：区間の中で 1 度でも移動・回転が成功するとロック猶予が戻るので、低頻度の入力でも固定は起きにくい

| rate | 1 系列で固定が起きる確率 | 3 系列で 1 度も起きない確率 |
|:--|:--|:--|
| 0 | 1.000 | 0.0000 |
| 0.01 | 0.352 | 0.2723 |
| 0.02 | 0.122 | 0.6759 |
| 0.05 | 0.005 | 0.9846 |

ハードドロップ（T3）を先に実装しなくても、T2 の受入が通るようになる。
