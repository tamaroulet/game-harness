# v2r の追試可能性の自己監査（2026-09-30）

v2r（テトリス、falling-blocks）の目標を、門の効果の有無ではなく「基盤が健全であることを示し、第三者が追試・検証できる透明性を確立すること」に定め直した（`docs/design/v2r_protocol.md` §15.13、2026-09-30 の操縦士の決定）。本書は、その観点で実験系を監査した結果と、この PR で塞いだ穴、塞げずに開示するものを並べる。

### 1.1 監査の途中で見つかった実例：agy の自動更新（2026-09-30）

変異の診断を回そうとしたところ、環境の照合が `cli.agy：実測 '1.2.12'、固定 '1.2.11'` で止まった。v2r-dry-03（2026-09-27）の後に、agy が人の操作なしに版を上げていた。照合があったので、違う実装役の版で走ることは起きていない。ただし、V2R-R（4 条件の走行）はこのままでは起動しない。

- 変異の診断は agy を使わないので、照合を OS・Python・dotnet・dotnet-stryker・テストのパッケージに絞った（`v2r_mutation.env_require`）
- agy の版をどうするかは §3 の 3

## 2. 塞げないもの（開示する）

1. **サンプリング**：temperature・top_p・seed は agy 1.2.11 では指定も記録もできない。同じ設定で追試しても、実装役の出力は一致しない。非決定性は「出力の全文の保存」で扱う（R=1 なので、ばらつきは推定しない。§15.13）
2. **agy のシステムプロンプト**：agy が内部で付け、保存できない（§7.1）。版（1.2.11）と、init が報告する道具の一覧を記録する
3. **作業場所のパス**：実装役に渡すプロンプトの先頭に、呼び出しごとに違う一時の作業場所のパス（`%TEMP%\harness-narrow\<乱数>`）が入る。プロンプトの中身のそれ以外は、凍結した入力から決定論で作られる
4. **提供側のモデル**：`gemini-3.8-flash-medium` の中身が提供側で変わっても、名前が同じなら検出できない。呼び出しの日時（ログ）を残す
5. **agy の会話の記録**：agy は `~/.gemini/antigravity-cli/brain/` に会話を残す（2026-09-30 の実測で 286 件）。ほかの会話の記録を読んだかは、作業場所の外への接触として検出して数える（`harness/agy_stream.py`）。読ませないことはできない
6. **非公開シード**：run-id から決まるので、第三者が同じ run-id で走らせれば同じシードになる。別の run-id では別のシードになる（導出の式は公開）

## 3. 人間の判断が要る点

1. `~/.gemini/GEMINI.md` の本文を Release のアーカイブに入れるか。入れないと、第三者は sha256 で「同じかどうか」しか確かめられない
2. v2r-dry-03 は provenance.json を導入する前の走行なので、ハーネスのコミットは記録から戻せない（env.json の時刻 2026-09-27T22:30:29 は、game-harness#128〔`a309102`〕のマージの 89 秒後で、その後の main の変更は game-harness#129 の文書だけなので、`a309102` で走ったと推定できる。作業ツリーが汚れていなかったことは確かめられない）。4 条件の R=1 の走行（V2R-R）は、provenance.json のある状態で行う
3. agy の版（§1.1）：(a) 1.2.11 に戻し、自動更新を止める（v2r-dry-03 と同じ実装役で 4 条件を揃えられる）、または (b) 1.2.12 を `config/environment.json` に固定し直す（main への PR。v2r-dry-03 の A0 と V2R-R の 4 条件で版が変わるので、V2R-R の A0 を比べる元にする）。総監督は (a) を勧める。どちらでも、自動更新を止める方法を手順に書く必要がある

## 4. 証拠として固定するもの

- **v2r-dry-03**（A0、T1〜T10）：天井（欠陥 0 件、受入 68/68、空虚な性質 0）を「フロンティアの実装役に対する、この系列の難易度のベースライン」として記録する。判定は `python -m harness.ab.v2r_ceiling --run-id v2r-dry-03 --accept-ceiling`（行の欠け・重なり・空虚な性質は、これを付けても不合格のまま）
- **変異の死滅率**（`harness/ab/v2r_mutation.py`）：オラクルの強さを示す特性値として、タスクごとの値を記録する。80% は本走に入る条件ではなくなった（系列を変えないので）。実装全体（T10、範囲 all）で 80.9%（186/230）、タスクごと（範囲 task）で 64.4%〜79.7%。表は `docs/design/v2r_dry03_ceiling.md` §6.3
- 記録の公開（pack → Release → verify）は V2R-U7 で、4 条件の R=1 の走行と一緒に行う
