# 紳士協定を機械的な拒絶に置き換える 3 つの防壁（ADR-002）

- 状態: 防壁①は配置済み（`.claude/settings.json`）。防壁②③は方針のみで、コードは変更していない
- 前提: Issue 12 カナリアが 1 回で合格（`docs/design/canary_issue12.md`）。再現性の検証は打ち切り
- 決定（2026-09-21、人間の指示）: これ以降の要件は、文章による注意ではなく、機械が拒絶する形で実装する

## 1. 目的

過去の 2 回の破綻は、どちらも「書いてある規約を守る」という前提が崩れて起きた。そこで次の 3 つを、書いてあるだけの規約から、機械が拒否する仕組みへ置き換える。

| 防壁 | 守るもの | 拒絶する主体 |
|:--|:--|:--|
| ① 総監督の視界 | 総監督がコード・テスト・生ログを見ないこと | Claude Code の権限設定 |
| ② 単位定義の形 | 分解役（Layer 2）が手計算の式や C# を書かないこと | ハーネスのスキーマ門 |
| ③ テストの階層 | 実装役（Inner Loop）が不変条件テストに触れず、見もしないこと | ディレクトリとプロジェクトの物理分割、ハーネスの配線 |

## 2. 防壁①：総監督の deny ルール（配置済み）

`game-harness/.claude/settings.json` に置いた。拒否する範囲は次のとおり。

- `Read` / `Edit` で拒否するもの
  - `C:\src` 以下のすべての `*.cs`
  - falling-blocks と unity-2d の `Game/Assets/Core/**`・`tests/**`
  - worktree 置き場 `C:\src\.local\wt/**`
- `Bash` / `PowerShell` で拒否するもの
  - `dotnet test` を含むコマンド
  - `.cs` のファイル名を含むコマンド
  - `Assets/Core` / `Core.Tests` / `*/tests` を含むコマンド

**配置後に確認した結果：** ダミーの `.cs` を使い、`Read`、`cat`、`dotnet test` を含むコマンドの 3 通りを試した。3 つとも権限設定で拒否された。

**影響範囲：** このリポジトリで起動するすべてのセッションに効く。ハーネスは Python なので、ハーネス改修の作業は妨げない。

**残る穴（正直に書く）：** 権限ルールはコマンドの文字列で照合する。そのため次の 2 つは塞げない。
- ファイル名を文字列に書かずに参照する方法。グロブ（`*.c[s]`）、変数、`python -c` などで回避できる。確認用のダミーファイルを消すときに、実際にグロブで通ってしまった
- ディレクトリ単位の再帰検索。`grep -r` をリポジトリの根に向けて使う場合

完全に塞ぐには、OS レベルのサンドボックス（`sandbox.filesystem.denyRead`）が要る。ただしサンドボックスは総監督のすべてのシェルコマンドを閉じ込める。パイプラインの起動、git push、実装役（agy）の呼び出しまで閉じ込めるので、今回は有効にしない。穴を突いた事例が 1 件でも観測されたら、サンドボックスを有効にする。

## 3. 防壁②：単位定義のスキーマ門

### 3.1 何を拒絶するか

「C# 構文が混ざっていたら REJECT」を文字どおり実装すると、今の `issue_12.json` が通らない。`prompt` に型名とメンバーのシグネチャが書かれているからである。そこで次の 2 つを区別し、拒絶するのは後者だけにする。

- **インターフェース宣言**：作るものの形。型名、種類、メンバー名、型。単位の契約そのものなので残す
- **オラクル**：期待値と、それを導く計算。ここに手計算が入り込む

### 3.2 単位定義 v2 の形

- `schema: 2`
- `interface`：型の一覧。各型は `name`、`kind`（enum / struct / class）、`members[]` を持つ。メンバーは `name`、`type`、`kind`、`params[]`、`static` を持つ。値はすべて列挙値か識別子で、C# の文字列は置かない（2026-09-21 裁定：C# 構文の生文字列は許さず、構造化フィールドだけで表す）
  - 型の表記は「識別子」「識別子<識別子>」と、それぞれの末尾に `?` を付けた形だけを受理する。式、本体、属性、修飾子の並びは書けない
- `acceptance.cases`：受入条件の表。1 行が 1 回の状態遷移に対応する
  - `given`：事前状態。公開状態のフィールドをリテラルで書く
  - `op`：操作 1 つ。公開操作の列挙値から選ぶ
  - `expect`：事後状態。リテラルで書く
- `prompt`：自然言語だけ

### 3.3 バリデータ門の規則（機械判定のみ）

1. JSON Schema に適合すること。未知のキーがあれば拒絶する
2. `given` / `expect` の値はリテラルだけ。使えるのは整数、真偽、列挙のメンバー名、盤面の行を表す固定長の文字列。演算子・括弧・関数呼び出し・変数参照を含む文字列は拒絶する
3. 1 行に置ける `op` は 1 つだけ。複数ステップの列は拒絶する（horizon = 1）
4. `prompt` の中のコード表記（バッククォート）は、`interface` で宣言した識別子と、whitelist にあるパスだけを許す。コードフェンス、`;`、`{`、`=>` は拒絶する
5. **期待値は GDD に拘束する**（2026-09-21 裁定）。`expect` の各値は次のどれかでなければならない
   - `{"same": true}`：`given` から変えない
   - `{"param": "PR-xx"}`（座標などの成分なら `"index"` を付ける）：構造化仕様 §5 の外部パラメーターから引く。構造化仕様の `gdd-sha256` が今の GDD と一致しない場合は、引いた値を信用せずに拒絶する
   - `{"given": "<フィールド>", "add": 1}` または `"add": -1`：1 回の遷移で起きる 1 単位の増減だけ
   - 自明なリテラル：`0`、`1`、`true`、`false`、`null`、空の列、列挙のメンバー名

   上のどれにも当たらない数値のリテラル（分解役が独自に計算した値）は拒絶する。あわせて、各行の `rule` には構造化仕様の ID（LP / ST / RL / IF / PR）を必須とし、仕様に存在しない ID は拒絶する
6. 門に落ちた単位は、パイプラインを起動しない。終了コードは 2 とし、スケジューラを止める。壊れた単位のまま Issue を回し続けないためである

### 3.4 テストコードは誰が書くか

C# のテストコードは、ハーネスの決定論的な生成器が `acceptance.cases` から出力する。分解役は C# を 1 行も書かない。

**このスキーマで手計算そのものは消せない**ことは明記しておく。期待値のリテラルは、依然として誰かが計算したものである。スキーマが保証するのは次の 2 点までである。
- 期待値は、GDD の文言だけで 1 ステップ分を確かめられる大きさに収まる（horizon = 1）
- 複数ステップにわたる正しさは、期待値を持たない不変条件テスト（防壁③）に任せる

## 4. 防壁③：テストの物理的な階層分離

### 4.1 分け方

| 層 | 置き場所 | 中身 | 実行する者 |
|:--|:--|:--|:--|
| Unit | `tests/Unit/`（独立した csproj） | 防壁②の生成器が出力する、1 回の遷移ごとの表駆動テスト | 実装役の Inner Loop、CI |
| Invariants | `tests/Invariants/`（独立した csproj） | GDD の保存則・状態遷移の包括規約を、シード付きランダム操作列で検査する性質テスト | パイプラインの Outer 段と CI だけ |

### 4.2 規則

1. **Invariants は、実装役のサンドボックスに置かない。** フィルタで実行対象から外すのではなく、ファイルそのものを持ち込まない。見えないテストに合わせて書くことはできない
2. Inner Loop の高速検査は `tests/Unit` の csproj だけを実行する
3. Invariants が失敗したとき、実装役に返すのは「不変条件の ID と GDD の節番号」だけ。値、スタックトレース、テストコードは返さない
4. Invariants は期待値を持たない。宣言データ（ID、GDD の節、公開状態のフィールドに対する等式）から生成器が出力する。等式の文法は、公開フィールド名・整数・`+ - * =` に限る
5. Invariants の変更は、GDD の版が上がる PR でだけ許す。Core の実装と同じ PR で変えることは、門で拒絶する

## 5. 実装の順序と PR の分け方

防壁②と③は門の挙動を変える。そのため、それぞれを独立した PR にして人間のレビューを受ける。

| 順 | PR | 内容 | 門に触れるか |
|:--|:--|:--|:--|
| 1 | 本ブランチ | 防壁① の設定と本文書 | 触れない |
| 2 | 単位スキーマ v2 | JSON Schema とバリデータ門 | 触れる |
| 3 | テスト生成器 | `cases` から Unit テスト、宣言から Invariants テストを出力する。**生成器の自己テストを必須にする**（2026-09-21 裁定）：出力した C# が `dotnet build` を通ることを Python 側のテストで保証する。保証できるまで 4 に進まない | 触れない |
| 4 | テスト分割と配線 | 2 つの csproj、サンドボックスへの持ち込み除外、Outer 段、CI（falling-blocks 側も） | 触れる |
| 5 | 移行 | `issue_12.json` を v2 に書き換え、カナリアを 1 回走らせる | — |

5 のカナリアは、防壁を入れた後もループが壊れていないかの 0/1 判定である。ばらつきの調査はしない。
