# V2-RUN の実験設計の自己批判と、再実験の要否

- 状態: 見解（2026-09-26）。コードと走行はまだ変えていない。再実験は、この文書の合意の後に設計の PR を出す
- 前提: V2-RUN の報告書（`experiments/v2/results/run/report.md`、game-harness#104）、外部の査読で指摘された 3 点
- 数値は一次情報（`report.md`・`smoke/notes.md`・`summary_smoke0*.md`）から。推測の値は「見積もり」と書く

## 0. 結論

1. **V2-RUN は「防壁（門）が品質を保った」ことを示していない**。A にも同じ形式仕様・同じ門の知らせを与えたので、V2-RUN の A 対 B は「会話を積むか、毎回ゼロから始めるか」だけを比べる実験になっていた。しかも 40 タスクすべてが最初の提出で合格し、門は 1 度も働いていない。門の因果は、この走行からは言えない
2. **「B は費用 0.89 倍」「損益分岐 N* = 5」は取り下げる**。走行ごとの費用の範囲は A 0.2973〜0.4284、B 0.3107〜0.3618 USD で重なっており、差は走行のばらつきの中にある。N* = 5 は事前投資の B の分を 0 とした会計の上の値で、差 0.0159 USD は A の T5 の 1 タスクで決まっている。言えるのは「5 タスクの規模では、費用と秒に差が見えない」まで
3. **B の文脈は O(1) ではない**（T1 → T5 で +45〜47%）。最初の手番の思考は、タスクごとの中央値で B が A の 1.03〜1.57 倍。B が総費用で A を下回ったのは A のキャッシュ読みと入力（キャッシュに乗らなかった分）の大きさによるもので、B の構造による優位ではない
4. **再実験は要る。ただし同じ設計で N を増やすのではなく、問いを分けて設計し直す**。最優先は「門が働く条件で、門の効果を測る」こと（§3）。Phase 4 は、門の因果が確かめられるまで大きな投資をしない

## 1. 実験設計の自己批判

### 1.1 天井効果と、対照群の消失

**何をしたか**：

| 版 | A に与えたもの | 理由（当時） |
|:--|:--|:--|
| v2.1c〜 | 細い作業場所、契約と既存の型の埋め込み | 公平性（game-harness#82） |
| game-harness#89 | **B と同じ検査の列（pipeline.judge）と同じ知らせ、同じ呼び出しの上限** | 試験制度の対称化。A は門が無いまま測定に進み、P2P を壊していた（v2-dry-05b・v2-dry-06・v2-smoke-01 の A で 5 件） |
| v2.3（game-harness#100） | 性質・関数の定義・interface を A・B に同じく（N1 を A・B 対称に適用） | 共有の入力は両条件に同じく当てる、という方針（`v2_b_efficiency.md` §3） |

**結果として**：V2-RUN の A は「形式仕様＋門の知らせ＋細い作業場所＋会話の累積」、B は「形式仕様＋門＋細い作業場所＋ステートレス」で、**差はステートレスかどうかの 1 点だけ**になった（`report.md` §4.1 に自分でそう書いている）。「門のおかげで品質が保たれた」を問うには、門を持たない条件が要るが、それが実験系に無かった。

**なぜそうしたか（盲点）**：

1. **公平性を「同じものを渡す」ことと取り違えた**。A が P2P を壊したとき（v2-dry-06 など）、それは「門が無いと先祖返りが起きる」という、まさに測りたかった効果の観測だった。それを「試験制度の不公平」と捉えて A にも門を与え、効果そのものを両条件から消した
2. **改善の対象を「スモークが通ること」にした**。T2 の前提の抽出（game-harness#94）、T5 の受入の修正（#88）、v2.2・v2.3 の文面の整理は、どれも実装役が 1 回で通る方向に働いた。スモークの成功を目的にして最適化を重ねた結果、タスクは易しくなり、V2-RUN は天井（40/40、最初の提出も 40/40）に張り付いた。測定器が差を出せない状態を、自分で作った
3. **門の働きを見る指標を用意していたのに、それが 0 のときの意味を検討しなかった**。最初の提出の測定（game-harness#90）は門の効果（最初 → 最終）を見るためのもので、スモークでは働いていた（v2-smoke-03 の B の T1 は P2P 5 → 0、v2-smoke-04 の T3 は両条件とも 2 → 0）。V2-RUN で 0 回になったとき、「健全」と読み、「門の効果を測れていない」とは読まなかった

### 1.2 損益分岐の会計

| 項目 | V2-RUN の扱い | 問題 |
|:--|:--|:--|
| F_shared | 1.202043 USD を両辺に置く | 両辺で相殺されるので、損益分岐に効かない |
| F_B_only | 0（v1 と同じ方針：「既存の資産の流用で、按分しない」） | ハーネスの門（whitelist 検査・反例の抽出・性質テストの生成・不変条件・guard）の開発と保守の費用が 0 になっている。v2 の工程だけでマージした PR は 31 件（進捗の CLI だけの PR を除く。`report.md` §5.2）。その費用は測っていない |
| 総監督の手直し | 含めない（`precost.json` の director_edits） | 人手（またはエージェント）の手直しの費用が 0 |
| 総監督（Claude Code）の費用 | 測っていない | 設計・実装・監視の費用が、どちらの条件にも入っていない |

- この会計では、B の固有の費用がすべて 0 になるので、損益分岐は「走行の費用の累積」だけで決まる。産業の総保有コスト（TCO）の比較としては成り立たない
- さらに、走行の費用の差自体が走行のばらつきの中にある（§0 の 2）。**N* = 5 は、会計の仮定と 1 タスクの外れ値の両方に依存した値で、主張として出すべきではなかった**

### 1.3 文脈の伸びと思考のインフレ

| 指標 | 値（`report.md`） |
|:--|:--|
| B のプロンプトの字数（T1 → T5） | 24,295 → 35,106〜35,673（+45〜47%） |
| 伸びの内訳 | 単位定義（性質の累積）+4,701、埋め込み（書き換えてよいファイル）+6,219（v2-run-01） |
| 最初の手番の思考（タスクごとの中央値、B / A） | T1 1.03、T2 1.57、T3 1.44、T4 1.46、T5 1.46 |
| 思考の合計（20 呼び出し） | A 105,335、B 133,969（1.27 倍） |

- 自己批判（`v2_2_architecture_self_critique.md` §1.3）で O(N)・O(コード) の伸びを指摘し、N3（足跡で絞る）・N4（本体でなく境界）を Phase 4 の前提に回したまま本走に入った。**B の存在理由（文脈が伸びない）を満たさないまま、B の優位を測った**
- 思考の多さは、契約と性質の式だけを読んで制約を解く負担か、会話の文脈が無いことの負担か、この記録からは分けられない。どちらにしても、B の出力の費用は A より高く、総費用で下回ったのは A の側の入力の大きさ（キャッシュに乗らなかった分を含む）という外部要因による

### 1.4 まとめ：V2-RUN から言えること・言えないこと

| 言えること | 言えないこと |
|:--|:--|
| 5 タスク・この難しさでは、A（会話を積む＋門）も B（ステートレス＋門）も、受入・P2P・不変条件をすべて守った | 門が品質を保った（門は 1 度も働いていない） |
| 5 タスクの規模では、費用と秒に差が見えない | B の方が安い・損益分岐 N* = 5 |
| ハーネスの配管（契約の生成、性質テスト、非公開シード、測定、監視、モデルの記録）は 40 タスクを通して止まらずに動いた | B の文脈が長期で伸びない（伸びている） |
| 実装役の呼び出しは、健全に終わるようになった（error_message 0、TTL 0） | 長期の運用で A が破綻する（5 タスクでは現れない） |

## 2. 再実験の要否

**要る**。本基盤の最終の目的（ゲーム開発・3D 連続力学系を、人間の介入なしに長く開発し続ける）の土台は「門が先祖返りと仕様のずれを止める」という因果で、V2-RUN はそれを確かめていない。この因果が成り立たないなら、Phase 4 で連続系の門（許容誤差・地平つきの性質、メタモルフィックテスト）を作る投資の前提が崩れる。

ただし、**同じ設計のまま N やタスク数を増やす再走は、しない**。門が働かない限り、何回走らせても天井に張り付く。

## 3. 再実験の設計の方針（合意を求める案）

### 3.1 問いを分ける

| 問い | 何を比べるか | 条件 |
|:--|:--|:--|
| Q1 門の因果（最優先） | 門の有無だけを変える | **A0**：自然言語の要求だけ、性質・関数の定義・門の知らせなし（産業の素朴な基準）／**A1**：A0＋門の知らせ（形式仕様なし）／**B−G**：B から門を外す（契約と性質の文脈だけ）／**B**：いまの B |
| Q2 形式仕様の効果 | 同じ門のもとで、形式仕様の有無 | A1 対 B |
| Q3 長期の費用 | 会話の累積とステートレス | タスク数を増やした系列で A 対 B。B は N3・N4 を入れた版と入れない版 |

- 測るのは全条件で同じ測定器（非公開シードの性質テスト・P2P・不変条件）。門の知らせを受けない条件（A0・B−G）も、測定は同じ
- 主な指標：**門が働いた回数**、最初の提出の不合格率、最終の P2P の破壊、**門をすり抜けた欠陥**（門に無い非公開の検査で見つかったもの）、費用・秒、文脈の伸び

### 3.2 門が働くタスクにする

- 天井を避けるため、先祖返りの圧力がある系列にする：前のタスクの振る舞いを壊しやすい変更（リファクタリング、横断的な仕様の変更、同じメンバーを複数のタスクが触る）を含める
- 事前に「A0 なら壊すはず」を乾式の走行で確かめてから本走に入る（天井の検査を先に置く）。A0 が全勝するなら、タスクがまだ易しい
- 自分でタスクを易しくする改善（前提の抽出など）は、測定器の修正（テストの欠陥）に限る。実装役が通りやすくなる方向の文面の整理は、条件を固定した後は入れない

### 3.3 会計

- F_B_only は 0 にしない。測れるもの（門の実行の秒と費用、宣言の手直しの回数と時間、総監督の呼び出しの費用）を測り、測れないもの（ハーネスの開発と保守）は幅で示し、損益分岐を F_B_only の関数として出す（感度分析）
- 費用の差は、走行のばらつき（範囲・四分位）と並べて報告し、範囲が重なるときは「差なし」と書く

### 3.4 順序と費用の見込み

1. この文書の合意
2. 再実験の設計の PR（タスクの系列、条件の定義、指標、停止条件、会計）。コードは条件 A0・A1・B−G を出せるようにするだけで、B の処置は変えない
3. 乾式の走行で天井の検査（A0 が壊すこと）
4. 本走

- 費用の見込み（見積もり）：V2-RUN の 1 条件 1 走行は 0.30〜0.43 USD（5 タスク）。20 タスク × 4 条件 × 4 走行なら、タスクあたりの費用が同じとして 19〜28 USD 程度。門が働けば再試行で増える。監視の上限は設計の PR で決める

### 3.5 Phase 4 との関係

- Phase 4 の設計（連続系の性質、到達可能性の診断など）は文書として進めてよいが、実装への大きな投資は Q1 の結果を待つ
- Q3（長期の費用）には N3・N4（文脈を足跡で絞る）が要る。これは Phase 4 の前提でもあるので、Q1 と並行して設計する
