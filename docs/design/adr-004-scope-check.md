# ADR-004 の段 1 の範囲の点検：環境の結合は、どれだけの不具合を起こしてきたか（2026-10-23）

- 書いた者：実行役（Claude Code、claude-opus-5-5）
- 目的：ADR-004 の K-13（7 つのポート）と K-14（Linux と意地の悪い Windows の CI）は、「環境と版の直書きが、ほぼすべての欠陥の共通の根」という見立てに依っていた。この見立ては前提の台帳に無く、数えてもいなかった。W-127・W-128 に入る前に、リポジトリの記録で数える
- 外部の情報は使っていない。全部、このリポジトリと H ラインの記録の実測である

## 1. 数え方

1. `git log origin/main --since=2026-09-01 --no-merges` の件名が `fix` で始まるコミット（49 件）を、1 件ずつ件名で分けた
2. H ラインの不合格の試行を、`python harness/failure_classes.py --queue <out>/hline/queue.json` で数えた
3. Git の外の走らせ役の不具合（棚卸しの D16）は、Git の記録に無いので別に挙げた

## 2. 結果

### 2.1 fix のコミット 49 件のうち、環境に起因するもの：15 件（31%）

| 種類 | 件数 | コミット | 防ぐもの |
|:--|--:|:--|:--|
| ファイルの文字コード・BOM・改行の崩れ | 5 | 9f9ffa8・64284fe・96031d5・10f40fa・203af92 | リポジトリの文字の衛生の検査（BOM 無し・LF）。境界でも Linux の CI でも防げない（書いたのはエージェントと手作業） |
| Windows のプロセスの扱い（窓・コマンドラインの長さ・8.3 の短い名前・出力の文字コード） | 4 | 1841aef・a04a186・56f9102・e4bf273 | process のポート（起動の仕方を 1 か所にする）と、意地の悪い Windows の CI |
| CLI・道具の版のずれ | 4 | c61f46f・5805369・ee48714・a4bc042 | 環境の台帳と envcheck（W-126 で入れた） |
| CI の基盤の振る舞い | 2 | 1967864・2779b86 | 個別（NuGet の並列の競合、runner の文脈） |

残りの 34 件は、ハーネスの論理・設定・台帳・試験の書き方で、環境とは関係しない。

### 2.2 H ラインの不合格の試行：infra は 0 件

- 不合格の試行は 37 件（2026-10-06〜10-21）。分類は `test` 20 件・`不明` 15 件・`full_suite` 1 件・`repeat` 1 件
- `infra`（基盤の故障）は 0 件だった
- ただし、環境が原因で試験が落ちても `test` に入るので、これだけでは「環境の故障が無い」とは言えない

### 2.3 Git の外：走らせ役の JSON の読み取り（D16）

- PowerShell 5.1 の文字コードで、外側の周期の処理が 452 回続けて落ちた
- 被害が最も大きい 1 件で、W-61 はこれで止まっていた
- 防ぐのは W-129（走らせ役を Git に入れ、Python に移す）である。ポートでも Linux の CI でもない

## 3. 読み取り

- 環境の結合は、実在する不具合の源である（fix の 3 割と、最大の停止）。ただし「ほぼすべての共通の根」ではない
- 15 件と D16 のうち、**Linux の CI で見つかったはずのものは 0 件**だった。どれも Windows に固有のものか、CI の基盤の問題である。目的（この 1 台の Windows で外側の周期を回す）にも、Linux で動くことは含まれない
- **ポートで防げたはずのものは、process の 4 件だけ**だった。vcs・forge・agent・host・engine の境界に当たる不具合は、この期間に 0 件
- 版のずれの 4 件は、W-126 の台帳と envcheck で塞がった
- 文字コード・BOM・改行の 5 件は、決定論の検査（W-133 の側）で安く塞げる

## 4. 段 1 の範囲の見直し（ADR-004 の改訂で決める）

| タスク | 前 | 後 |
|:--|:--|:--|
