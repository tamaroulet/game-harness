## 3. 問い 3：見落としている根本の問い・置いたままの前提

### P1. 今の判定は、狙う型で誤りの向きが変わる。誤りを抑えると鈍くなる。L8 は、これを確かめる手順を持たない

- **事実：**
  - 狙いの直りの判定は「直した対が壊した対より多く、かつ直した対が 2 以上」（承認:51）。対は、基準の 2 回の走りのそれぞれの先端から 1 対ずつ（承認:50）。この下限はコードに無く、比べの道具は直した対と壊した対の数を書くだけ（`harness/bench_pair.py:280`）。承認が決めているのは 1 周目の回数と費用（承認:47）。

  - v3 の落ちの読みでは、F1 は 1 回目の走りだけ（B07 の段 2：v3:742。段 4 と連鎖の段 6：v3:833）、F2（B08 の段 4）と F3（B09 の段 6）は 2 回とも 1 段ずつ（v3:834-835）。F2 は直しに要るコマンドが面の外（v3:834、承認:28）。だから、提案役が面の中で狙うのは F3 になりやすい（推測）。門の試行を 2 回使った 13 回の走りの型は、リポジトリに無い。
  - 同じ版でも段の結果は揺れる（B07 の段 2：1 回目 1/12、2 回目 12/12。v3:696）。
  - L8 の条件は「2 周を続けて人の手なしで回し、取り込んだ改善のうち 1 件以上が保留の組でも悪くしていない」（v3:374）。
  - 木の req.self-improvement の achieved_when は「点を下げずに取り込む」（`tree.yaml:23-25`）。その前提の req.measurable は、ベンチが改善を検出できるか（req.benchmark-sensitivity）を、仮説のまま置く（`tree.yaml:47,394-402`）。
- **推測（付録 B。段ごとの通る見込み p は 2 回の走りからは決まらないので、置いた値。最悪の値は、p を 0.05〜0.95 で振ったときの最大）：**

  | 狙い（対の数） | 決まり | 効かない変更が通る見込み | 効く改善が通る見込み（置いた効き） |
  |:--|:--|:--|:--|
  | 1 段（2 対）：F3 か F2 | 今の決まり | 最悪 6.2%（p=0.1 なら 0.8%） | 約 20%（0.1→0.5）〜66%（0.1→0.9） |
  | 2 段（4 対）：F1 | 今の決まり | 最悪 23.8%（置いた p で 10.4%） | 約 33%（1 回目の先端で 0.3→0.7） |
  | 2 段（4 対）：F1 | 直した対 − 壊した対 ≥ 3 | 最悪 3.5% | 約 4.5% |
  | 3 段（6 対）：F1 | 今の決まり | 最悪 34.0%（置いた p で 19.9%） | 約 57% |
  | 3 段（6 対）：F1 | 直した対 − 壊した対 ≥ 3 | 最悪 7.3% | 約 18.5% |

  - **今の決まりのまま対を増やすと、効かない変更が通る見込みも上がる。** p=0.1 の段で対を 2・4・6・8 にすると 0.8%・4.3%・9.1%・14.3%、p=0.5 なら 6.2%・23.8%・34.0%・38.6%。対を増やすなら、下限も一緒に上げる要がある。
  - **誤りを抑える決まりにすると、鈍くなる。** 効く改善を拾う見込みは、効きの大きさ（新版の p）で決まる。同じ版どうしの対では測れない。
  - **再現を条件にすると、誤りは小さくなる。** 新しい開始の木からの対でもう一度通ることを求めると、効かない変更が 2 度とも通る見込みは、1 段で最悪約 0.4%（6.2% の 2 乗。独立と置いた）。効く改善が 2 度とも通る見込みは約 4〜43%。
  - 回帰の守りの「2 回とも通った 13 段のうち、新版で落ちたのは 1 段以下」（承認:53）は、13 段が各 0.9 で通るなら約 58%、0.95 なら約 83% で満たされる。効く改善が片方だけ落ちた 3 段を 0.5→0.8 に上げても、約 62%・86% と、ほぼ同じ。効きを見分けない。
  - 止め方：効く提案だけでも、2 周で 1 件も取り込まない見込みは約 21〜78%。効かない提案だけで 2 周で 1 件以上を取り込む見込みは、F1 の 6 対を今の決まりで狙えば約 22〜30%、F3 なら約 1〜10%。「N 周で 0 件なら止める」の N は、検出力から決めないと、誤って止まるか誤って進む。
- **損：**
  - 今の決まりのまま 2 段以上を狙うと、効かない変更を取り込みうる。
  - 決まりを直すと、効く改善の多くを捨てる。周の数がかさむ。HB の外れの兆し「3 周で候補 0 件」（v3:405）も、効く提案でも出うる。
  - これを確かめないまま L8 を「確立」と書き、L7 の自動化を作ると、効きの分からない周期を人の手なしで回す道具になる。
- **確かめ方：**
  - 1 周目の決まりは、p に依らずに誤りを抑える形で、L6 の前に決める（Q3）。
  - 2 周目からの対の数は、L6 の対の旧版の結果で溜めた p から、その周の結果を見る前に決める。
  - L7 の前に、再現（新しい開始の木からの対）を求める。
  - 決まりの細部は B-measure に預ける。

    dist = {(0, 0): 1.0}
    for po, pn in zip(pold, pnew):
        f, b = (1 - po) * pn, po * (1 - pn)
        nd = {}
        for (fx, br), pr in dist.items():
            for dx, db, q in ((1, 0, f), (0, 1, b), (0, 0, 1 - f - b)):
                nd[(fx + dx, br + db)] = nd.get((fx + dx, br + db), 0) + pr * q
        dist = nd
    return dist
def rule_now(d, need=2):  return sum(p for (fx, br), p in d.items() if fx > br and fx >= need)
