## 3. 問い 3：見落としている根本の問い・置いたままの前提

v3 は、P1・P2 の弱さを HA・HB の外れの兆し（v3:404-405）として書いている。見落としているのは弱さそのものでなく、それを確かめる手順と、確かめる前に凍結してよいかの問い。

### P1. 取り込みの判定は弱い。どの型を狙うかで誤りの向きが変わる。L8 は、その弱さを確かめる手順を持たない

- **事実：**
  - 狙いの直りの判定は「直した対が壊した対より多く、かつ直した対が 2 以上」（承認:51）。対は、基準の 2 回の走りのそれぞれの先端から 1 対ずつ（承認:50）。
  - 提案役が選ぶ型は 1 つで、「両方の走りで出た型を先に見る」（`docs/prompts/proposer.md:15-17,30`）。
  - v3 の落ちの読み（v3:833-835）では、F1 は 1 回目の走りだけ（B07 の段 2・4 と連鎖の段 6）、F2（B08 の段 4）と F3（B09 の段 6）は 2 回とも 1 段ずつ。F2 は直しに要るコマンドが面の外（v3:834、承認:28）。だから、提案役が面の中で狙うのは F3 になりやすい（推測）。門の試行を 2 回使った 13 回の走りの型は、リポジトリに無い。
  - 同じ版でも段の結果は揺れる（B07 の段 2：1 回目 1/12、2 回目 12/12。v3:696）。
  - L8 の条件は「2 周を続けて人の手なしで回し、取り込んだ改善のうち 1 件以上が保留の組でも悪くしていない」（v3:374）。
  - 木の req.self-improvement の achieved_when は「点を下げずに取り込む」（`tree.yaml:23-25`）。その前提の req.measurable は、ベンチが改善を検出できるか（req.benchmark-sensitivity）を仮説のまま置く（`tree.yaml:47,394-402`）。
- **推測（付録 B。段ごとの通る見込みは 2 回の走りからは決まらないので、置いた値）：**

  | 狙う型（対の数） | 効かない変更が通る見込み | 効く改善が通る見込み |
  |:--|:--|:--|
  | F3（B09 の段 6、2 対） | 約 1%（p=0.1）〜6%（p=0.5） | 約 20%（0.1→0.5）〜66%（0.1→0.9） |
  | F1（B07 の段 2・4、4 対） | 約 10% | 約 33%（1 回目の先端で 0.3→0.7） |
  | F1（段 6 も含め 6 対） | 約 20% | 約 57% |

  - **今の決まりのまま対を増やすと、効かない変更が通る見込みも上がる。** p=0.1 の段で対を 2・4・6・8 にすると 0.8%・4.3%・9.1%・14.3%、p=0.5 なら 6%・24%・34%・39%。対を増やすなら、直した対の下限（差の閾値）も一緒に上げる要がある。
  - **何対あれば足りるかは、段ごとの p で決まる。** 例の目安（効かない変更が通る見込み 1 割以下、効く改善を拾う見込み 5 割以上）に届く形は、次のとおり（置いた値での計算）。どちらに当たるかは、揺れを測らないと分からない。
    - F3 で効きが 0.1→0.5 なら、先端ごとに 2 対（4 対・段の走り 8 回・約 2,000 万）、直した対 2 以上で 4.3%・61%。
    - F1 で効きが 0.3→0.7 なら、先端ごとに 4 対（段の走り 32 回・約 8,000 万）、直した対 5 以上で 7.5%・54%。効きが 0.3→0.5 なら、先端ごとに 5 対でも届かない。
  - 回帰の守りの「2 回とも通った 13 段のうち、新版で落ちたのは 1 段以下」（承認:53）は、13 段が各 0.9 で通るなら約 58%、0.95 なら約 83% で満たされる。回帰を起こさない変更なら、効く改善にも効かない変更にも同じ見込みで、効きを見分けない。
  - 例：今の決まりで F1 の 6 対を狙い、開発の組の回帰の守りまで通るとき、提案が本当に効く見込みを 2〜5 割と置くと、取り込んだ改善が本当に効いている見込みは約 4〜7 割。
  - 止め方：取り込みが 1 周あたり 0.12〜0.54 の見込みで起きるなら、効く提案だけでも 2 周で 0 件の見込みは約 21〜78%。効かない提案だけでも、2 周で 1 件以上を取り込む見込みは約 23〜31%。「N 周で 0 件なら止める」は、N を測った数から決めないと、誤って止まるか誤って進む。
- **損：**
  - 1 周の取り込みが、効いた改善かを言えない。F3 を狙えば、効く改善の多くを捨てる。HB の外れの兆し「3 周で候補 0 件」（v3:405）も、効く提案でも出うる。
  - これを確かめないまま L8 を「確立」と書き、L7 の自動化を作ると、効きの分からない周期を人の手なしで回す道具になる。
- **確かめ方：** 凍結の前に揺れを測り（§4-2）、その数から、目安に届く判定の形（対の数と直した対の下限）・1 周の費用・止め方（何周で 0 件なら止めるか）を出す。決まりの細部は B-measure に預ける。

```python
import itertools
def judge(pold, pnew, need=2):
    tot = 0.0
    for outs in itertools.product([(0,0),(0,1),(1,0),(1,1)], repeat=len(pold)):
        pr, fx, br = 1.0, 0, 0
        for po, pn, (o, n) in zip(pold, pnew, outs):
            pr *= (po if o else 1-po) * (pn if n else 1-pn)
            fx += (o, n) == (0, 1); br += (o, n) == (1, 0)
        if fx > br and fx >= need:
            tot += pr
    return tot
```
