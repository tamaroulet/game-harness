# Issue 12 を固定カナリアとして自律ループを再走させる方針

- 状態: 方針のみ。コードは変更していない
- 前提: falling-blocks GDD v8（sha256 `a07e9ccc…`）、`tools/units/issue_12.json`、Issue 12 の実装は main に取り込み済み（`9311afa4`）
- 決定（2026-09-21、人間と合意）: カナリアの対象は falling-blocks。捨て枝で走らせる。CI まで通す。所要時間は門にしない

## 1. 目的

完成済みの Issue 12 を物差しとして固定する。そのうえで、ハーネスが無人で起動し、白紙から次の 4 段階を完走できるかを確かめる。

1. 実装
2. 自己修復
3. 高速検査
4. CI（Outer Gate）

確かめる対象はゲームではなくループの安定性である。Issue 15 以降（自然落下・接地・固定）は凍結したまま動かさない。

## 2. 前提の確認

- GDD v8 は、Issue 12 の範囲について閉じている。対象は §1 盤面、§6 公開状態、§7 Ready 初期状態、§8-5 シード注入。`docs/spec/questions.md` の未解決質問は 0 件
- 憲章草案のコマンドにあった `--project unity-2d` は誤り。`issue_12.json` は falling-blocks の単位である
- 「45ms」はテレメトリにも TIMELINE にも記録がない。前回の実績は「高速検査 75 件・失敗 0・skip 0・差分 203 行・試行 1 回」
- パイプラインは PR の作成と merge をしない。ただし `--repo-dir` の現在ブランチに対して、次を無条件に push する
  - 実装
  - 失敗時の revert
  - TIMELINE

  push を止める起動フラグは無い

## 3. 決定

1. **標本は機械的な除去で作る。** main から `issue_12.json` の `impl_files` 6 件を削除した状態を出発点にする。スタブを手で書かない。書き手ごとに出発点が変わり、固定標本にならないためである
   - 受入テスト `tests/Core.Tests/**` は main とバイト一致させる
   - whitelist 外で main との差分を許すのは、削除したファイルに付随する Unity メタデータだけ。扱いは現場が決め、理由を記録する
2. **捨て枝 `test/canary-issue-12` で走らせ、origin への push を許可する。** CI まで通さないと、ループの半分しか実証できないためである
   - 禁止する操作: PR の作成、main への merge、承認（承認は人間専用で、カナリアでは誰も行わない）
   - 走行ごとに、ローカルとリモートの両方の枝を削除する。捨て枝に書かれた TIMELINE も枝ごと捨てる
3. **起動前に 2 点を確認する。** どちらか一方でも満たさなければ起動しない
   - `--repo-dir` がカナリア用 worktree を明示的に指していること。省略した起動や、main チェックアウトを指す起動は禁止する
   - `test/**` への push で、必須チェック `test` が発火すること。発火しない場合は CI 待ちで止まる
4. **起動コマンドは次のとおり。**
   ```bash
   python harness/pipeline.py --project falling-blocks --unit tools/units/issue_12.json --repo-dir <canary worktree> --telemetry <out>/canary_<n>.json
   ```
5. **所要時間は門にしない。** 試行回数と壁時計秒をテレメトリに記録し、推移だけを見る

## 4. 合格条件

判定には高次テレメトリだけを使う。

1. 人間の介入なしで、PASS・終了コード 0 になること。介入なしとは、起動コマンド 1 回だけで、途中の入力が無いこと
2. 高速検査が失敗 0・skip 0 で、required_tests の 3 クラスがすべて実行されていること
3. whitelist 外の差分が 0 で、差分が 250 行以内であること
4. ハング・部分コミット・main への push が無いこと。どれか 1 つでも起きれば、結果にかかわらず不合格

終了の種類ごとの扱いは次のとおり。パイプラインは DISPUTE と REJECT の打ち切りを、どちらも終了コード 1 で返す。

| 終了 | 終了コード | カナリアの扱い |
|:--|:--|:--|
| PASS | 0 | 合格候補。上の 1〜4 で判定する |
| DISPUTE | 1 | 安全に止まったが不合格。Issue 12 の受入テストは前回 1 回で通っているので、異議は誤りと扱う。論点を 1〜2 行で報告する |
| REJECT で打ち切り | 1 | 不合格 |
| ABORT | 2 | ループの判定ではなく環境の故障。原因を直して走り直す。回数には数えない |

試行回数は門にしない。所要時間と同じく記録して、推移だけを見る。

## 5. 守るもの

- falling-blocks の main には痕跡を残さない。ブランチ・コミット・TIMELINE・Issue・PR のいずれも対象
- 走行中は `issue_12.json`・GDD v8・受入テストを凍結する。どれかが変わった回は、比較対象から外す
- ハーネスのコードは変えない。門・指標・承認機構にも触らない
