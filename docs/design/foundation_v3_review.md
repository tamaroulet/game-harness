## 2. 確定仕様の項目ごとの計画

### Layer 1 統治層（思考役の無菌化）

- Claude IDE（総監督）のセッションで、Bash・PowerShell・Edit・Write・NotebookEdit をクライアントの設定で無効にする。残すのは Read・Grep・Glob と対話だけ
- 設定の変更は**人間が行う**（自分の権限を自分で書き換える操作は、統治層の外から行うべきもの）
- 入力は MUC（構造化最小診断：契約違反の ID と最小の反例）のみ。生ログ・TRX・作業ツリーは Read の deny で遮断する（既存の deny 22 件を、作業ツリーと走行の出力のすべてに広げる）
- MUC は Layer 2 が生成し、決まった置き場所にファイルとして書く。総監督はそれを Read するだけ

### Layer 2 実行基盤（`driver.py`）

- 作業ツリーはタスクごとに `wt/<task>-<uuid>`。同期削除はしない（Detach）。後片付けは非同期
- agy・テスト・ビルドのすべてのプロセスを Windows Job Object（`KILL_ON_JOB_CLOSE`）の配下で起動する
- インフラ例外（タイムアウト・クラッシュ）は agy に見せず、別の UUID で作業ツリーを作り直して自動再試行する
- agy の自動更新は ACL（`icacls` の Deny）で止める。ホストのセキュリティ設定の変更なので、**人間が実行する**

### Layer 3 現場実装（agy）

- 実装役は agy、モデルは `gemini-3.8-flash-medium`。`model_flag` と ID を設定に書き、`harness/model_pin.py` で照合する（作業規約どおり）
- 新規の `.cs` ファイル・クラスの作成を許可する
- テストコードは見せない（防壁③を維持）

### Layer 4 検証門（Gate 1）

- 判定は Roslyn・ArchUnitNET・FsCheck PBT・受入テストの終了コードだけ。exit 0 で即時コミット
- Gate 2（インラインの LLM 主観レビュー）を廃止する
- Base 検査は `--filter` で合格済みタスクのテストだけを指定する。除外の JSON は全廃
- 修正ループは最大 3 回。未収束はスキップし `TODO.md` に記録して次へ

### Layer 5 保守層（Refactorer）

- 10 タスクごと、またはマイルストーンの完了時に、Claude CLI の Refactorer を非同期で起動する
- 合格条件は Gate 1 が 100% 通ること

## 3. 確定仕様のままでは成り立たない箇所（人間の決定が要る）

確定仕様に 100% 合わせると、仕様の中で互いに矛盾する、または今の作業規約と衝突する箇所が 6 つある。私が勝手に片方を選ぶと「自己判断での逸脱」になるので、推奨を添えて人間の決定に回す。

| # | 箇所 | 何が衝突するか | 推奨 |
|:--|:--|:--|:--|
| 1 | Layer 1 が「完全 Read-Only」なのに「方針・仕様（spec/ 永続ファイル）」を Layer 2 へ渡す | 書けない役は spec を置けない | A：総監督は対話で仕様の全文を出し、**人間がコミットする**（完全 Read-Only を守る）。B：Edit を `spec/**`・`docs/design/**` だけ残す（Read-Only ではなくなる）。確定仕様に忠実なのは A |
| 2 | 作業規約（CLAUDE.md）は総監督に毎ターン `harness.progress anchor`／`report` の実行と、PR の作成・`review` の記録を求めている | Bash を剥ぐと全部できない | Layer 2 が状態が変わるたびに report の出力をファイルに書き、総監督はそれを Read して貼る。PR の作成と記録は Layer 2 か人間。CLAUDE.md の改訂は人間が行う |
| 3 | `--filter "T1\|T2"` | (a) 部分一致だと `T1` が `T10`〜`T19` にも当たる。(b) 合格済みタスクの非公開シードの版（`_Hidden`）は受理の時点で門に使っていないので、base に入れると落ちうる | 確定仕様の方式のまま、(a) タスクの ID を区切りつきで一致させる（`T1` が `T10` に当たらない）、(b) フィルタは公開の受入テストに限る、の 2 条件を合格条件に入れる。合格済みタスクの一覧は既存の進捗の状態から取り、新しい記録は作らない |
| 4 | 「3 回失敗時：スキップし、TODO.md に記録して強制マージ」 | 失敗したパッチを強制マージすると、ビルドが壊れた場合に以後のすべてのタスクの base が落ちて、ライン全体が止まる | スキップ＝**パッチを捨てて**マージしない。TODO.md に記録して次へ。そのタスクに依存するタスクは、agy を呼ばずに連鎖してスキップする（無駄な呼び出しをしない） |
| 5 | 「exit 0 で即時コミット＆マージ」 | 記憶されている合意では、統合 PR の承認は人間（エージェントは承認しない）。自動マージは変異の検査が前提条件だった | タスクの成果はマイルストーンの統合ブランチへ即時コミット。統合ブランチから main へは、確定仕様の「マイルストーン合否判定」として人間が非同期に承認する。これで確定仕様のスループットと承認の規則が両立する |
| 6 | クライアント設定での工具剥奪の範囲 | `game-harness` の `.claude/settings.json` で Edit・Bash を剥ぐと、同じディレクトリで起動される Claude CLI（分解役・Refactorer）にも効いて、Layer 2〜5 が止まりうる | 剥奪は総監督のセッションにだけ効く場所に置く。Layer 2〜5 のエージェントには届かないことを合格条件に入れる |

加えて、確認が要る事項が 2 つ：

- Gate 2 の廃止の範囲：廃止するのは「実装コードへのインラインの LLM レビュー」。分解役の出力（単位定義）への監査（監査役・OpenAI）は Gate 2 に含めるか
- ArchUnitNET の行数の上限の値と、Refactorer のモデルの ID

## 5. 各段の合格条件（What のみ）

各段の検証コマンドは、Layer 2 側で書き、main への PR で `docs/progress.yaml` に定める（作業規約どおり）。総監督は次の性質を満たすことだけを求める。どれも、その障害を人工的に起こしたときの両方向（止まらないこと／正しく止まること）で確かめる。

### 段 1 統治層

1. 総監督のセッションでは、シェルの実行とファイルの編集が一切できない
2. 総監督のセッションからは、生ログ・TRX・作業ツリーが読めない
3. 総監督が受け取る診断は、契約違反の ID と最小の反例だけで、生ログの内容を含まない
4. 1〜3 の制限が、Layer 2〜5 のエージェントには及ばない
5. 総監督は、ファイルを読むだけで現在の進捗（report と同じ内容）を知ることができる

### 段 2 実行基盤

1. 同じタスクを何度始めても、作業ツリーのパスが重ならない
2. 走行が途中で落ちても、次の走行は前回の残骸に影響されずに始まり完了する
3. タスクが終わったとき、そのタスクで起動したプロセスの子孫が 1 つも残らない。ハーネス自体が強制終了した場合も同じ
4. 作業ツリーの削除の失敗が、タスクの結果に影響しない
5. agy の導入先が書き換えられない（ACL）。書き換わっていた場合は、agy を呼ぶ前に止まる

### 段 3 検証門

1. 未実装のタスクのテストが落ちても、Base 検査は通る
2. 合格済みのタスクのテストが 1 件でも落ちると、Base 検査は止まる
3. タスクの ID の一致は、別のタスクの ID に部分一致しない
4. 除外の JSON を読む経路が無い
5. Gate 1 の判定に LLM の呼び出しが無い
6. agy が新規の `.cs` ファイルを作っても、それを理由に拒否されない（テストのパスへの書き込みは引き続き拒否される）
7. 3 回で収束しないタスクは、パッチを捨てて TODO.md に記録され、ラインは次のタスクへ進む

### 段 4 自己回復

1. 1 回目だけタイムアウトする状況で、タスクは新しい作業ツリーで完了する
2. インフラ例外は agy の試行回数を消費せず、agy に見せない
3. インフラ例外が上限を超えて続くと、ラインは止まり人間に通知する

### 段 5 保守層

1. 10 タスクごと、またはマイルストーンの完了時に Refactorer が起動する
2. Refactorer の変更は、Gate 1 が 100% 通るときだけ受理される
