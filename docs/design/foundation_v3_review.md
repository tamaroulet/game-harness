## 1. 自己検証（3 点）

### ① 上位 AI のマイクロ化：過小評価だった（認める）

初版は「走行を固定したコミットから実行する」で代えたが、これは走行中のプロセスを守るだけで、**上位 AI が生ログと配管を見て、次のコミットで直しに行く**経路は何も塞いでいない。

この盲点の最も直接の証拠は、初版を書いたこの会話そのものにある。総監督（私）は見解を書くために `harness/pipeline.py` の `establish_base` を読み、剪定の候補として関数名（`task_test_classes`）まで挙げた。今の規則では許されている行為だが、方針文書を書く役が配管の行単位に降りている。F-0〜F-5 を同じ役が進めれば、テストが落ちるたびに同じことが起き、改修の過程で配管を壊す。初版にはこれを防ぐ手段が無かった。

結論：Facade と役の分離は、ロードマップの**先頭**に置く。他のすべての改修を守る前提だから。

### ② 物理防壁の後退：Job Object は後退だった（認める）。版はテレメトリが後退だった（認める）が、ACL も十分ではない

- **Job Object**：環境変数は「常駐を作らせない」だけで、ハングした `testhost.exe`、ハーネス自体が強制終了したときの孫プロセス、MuJoCo のようなネイティブ DLL を抱えたプロセスは殺せない。指摘どおり。費用の小ささを理由に保証を外したのは誤り。Job Object を保証とし、環境変数は平常時にロックを抱える時間を減らす補助に下げる。
- **版の固定**：「記録して進む」は、走行の結果が後から再現できなくなる。製造ラインでも再現性は要る。後退だった。
- **ただし ACL（`icacls` で `agy.exe` への書き込みを拒否）も防壁として不十分**：上の実測のとおり、更新は名前の変更で行われている。ファイルへの書き込みの拒否では名前の変更（削除の権限）は止まらない。止めるにはディレクトリの権限まで絞る必要があり、そうすると「どの権限を拒否すれば十分か」が更新器の実装に依存する（更新器が変われば黙って破れる）。
- **より強い物理防壁**：ハーネスが**固定した版の複製**（`C:\src\.local\tools\agy\<版>\agy.exe`）を絶対パスで呼び、**呼ぶ直前に sha256 を照合**する。PATH の `agy` は使わない。更新器が書き換えるのは全体の導入先で、複製には届かない。複製が何かの理由で書き換わっても、照合で必ず止まる（フェイルクローズド）。ACL は、この複製のディレクトリに**人間が**かける追加の層として残す（ホストのセキュリティ設定の変更なので、エージェントは実行しない）。

### ③ 順序の逆転：半分は認める。半分は原案の前提を訂正したい

- 認める点：無菌室の本質は「改修する者が迷走しない」ことで、それは①の Facade。初版はこれを持たないまま配管に入ろうとしていた。順序の逆転だった。
- 訂正したい点：原案は Step 1 を「大掛かりな配管の改修なしに即座に効く設定・物理防壁」としているが、5 件のうち設定だけで済むのは Facade の壁（フック）だけ。ホワイトリスト化は `establish_base`（base の測定）の書き換え、UUID の使い捨ては作業場所の生成と削除の書き換え、Job Object と版の複製はプロセスの起動の書き換えで、いずれも配管の改修。したがって Step 1 の中にも順序が要り、**Facade を最初に完成させ、残りはその壁の内側で、ハーネスが呼ぶ別の役が実装する**。

## 2. 再構成したロードマップ（原案の 3 段に沿う）

### 役の分け方（Step 1 の前提）

| 役 | 見えるもの・できること | 見えないもの・できないこと |
|:--|:--|:--|
| 総監督（IDE の Claude Code） | `docs/design/**` の編集、Facade の出力（固定の様式の要約）、`harness.progress`、`git`・`gh pr` | `harness/**` の編集、走行の生ログ、作業場所（`.local/wt/**`）、任意のシェル |
| 配管の実装役（ハーネスが呼ぶ別のエージェント） | 1 タスクのための作業ツリー（`.local/eng/<タスク>-<uuid>`）の中の `harness/**`・`tests/**`、そのタスクの検証コマンドの出力 | 他のタスク、走行の生ログ、ゲームのリポジトリ |

- 配管の実装役は、他のエージェントと同じく `model_flag` と正確なモデルの ID で呼び、`harness/model_pin.py` で照合する（作業規約どおり）。タスクごとに新しいコンテキスト。
- 総監督への入口は Facade の 1 本：`python -m harness.facade status | dispatch <タスク> | result <タスク>`。返すのは固定の様式（タスク・分類〔PASS／CODE_FAIL／INFRA／BLOCKED〕・件数・PR の URL）だけで、ログの行は返さない。
- 壁は 2 層：`.claude/settings.json` の規則に加えて、**PreToolUse のフック**（許可リストに無い道具の呼び出しを終了コード 2 で拒否する Python の小さなスクリプト）。部分一致の deny だけでは `cat` などで迂回できるため、許可リスト方式にする。フックはセッションの作業ディレクトリで役を見分ける（総監督は `C:\src\game-harness`、実装役は `.local\eng\*`）。

### Step 1：即時投入（根絶系）

| 順 | ID（案） | 中身 |
|:--|:--|:--|
| 1 | S1-1 | Facade と役の分離（壁のフック・許可リスト・Facade の要約・配管の実装役の呼び出し） |
| 2 | S1-2 | Job Object（KILL_ON_JOB_CLOSE）配下でのすべての子プロセスの起動 |
| 3 | S1-3 | UUID の使い捨て作業場所・同期削除をしない・起動時の掃除 |
| 4 | S1-4 | agy の固定した複製・呼ぶ直前の sha256 照合（ACL は人間の追加の層） |
| 5 | S1-5 | base 検査のホワイトリスト化（受理時に通ったテストの集合を引き継ぐ） |

S1-2 を S1-3 の前に置くのは、作業場所を放置しても、ロックを抱えたプロセスが確実に死んでいれば掃除が成功するから（S1-3 の検証が Job Object に依存する）。

**S1-1 だけは壁ができる前に作るので、例外として総監督（私）が実装し、人間のレビューで止める**。S1-1 のマージ以降、総監督は `harness/**` を編集しない。

### Step 2：配管投入（自己回復系・製造ライン化）

1. 製造ラインと実験の測定器の分離（`harness/ab/` と天井の検査・変異の記録を v2r の版でタグ止めし、製造ラインの経路から外す）
2. インフラ例外の Outer-Loop（終了コード・タイムアウト・起動失敗だけで分類し、新しい UUID の作業場所で上限つき再試行。実装役の試行回数は消費しない）
3. サーキットブレーカー（3 回で打ち切り、BLOCKED にして証拠を残し、依存しないタスクだけ進める。依存するものしか残らなければ止めて人間へ）
4. UTF-8／LF の強制と剪定（製造ラインの経路の行数に予算を置き、検証コマンドで測る）

### Step 3：Phase 4 の最小モデル

MuJoCo の剛体 1 個と床、不変量 1 つ（非貫通、または外力なしの運動量）、門 1 つ、ワーカー 1 つ。これが無人で 1 晩回ってから、v3.1 の並列化・誤差包絡線・調停を必要に応じて足す。

## 3. Step 1 のタスクの定義

共通：検証コマンドは `pytest` の 1 ファイル。**障害を注入して、ラインが止まらないこと／正しく止まることの両方向**を終了コードで見る。ログの文字列は判定に使わない。検証コマンドは main への PR で `docs/progress.yaml` に定める（作業規約どおり）。

### S1-1 Facade と役の分離

- 検証コマンド：`python -m pytest tests/test_director_wall.py -q`
- 合格条件：
  1. フックに道具の呼び出し（JSON）を与えたとき、総監督の作業ディレクトリでは次を拒否する（終了コード 2）：`harness/pipeline.py` の Edit、`.local/wt/**` の Read、`cat`／`type`／`Get-Content` で走行の記録を読む Bash・PowerShell、許可リストに無い任意のコマンド
  2. 同じく次を通す（終了コード 0）：`docs/design/*.md` の Edit、`python -m harness.facade status`、`python -m harness.progress report`、`gh pr view`
  3. 配管の実装役の作業ディレクトリ（`.local/eng/*`）では、その中の `harness/**` の Edit を通し、`.local/wt/**` の Read は拒否する
  4. 走行の生ログに識別用の文字列（番兵）を注入し、`harness.facade status` と `result` の出力に番兵が 1 件も現れない。出力は固定の様式の検査に通る
  5. `.claude/settings.json` にフックが登録されている（設定を読んで確かめる）
  6. `harness.facade dispatch` が配管の実装役を呼ぶ設定に `model_flag` と正確なモデルの ID があり、`python -m harness.model_pin` が通る

### S1-2 Job Object

- 検証コマンド：`python -m pytest tests/test_job_object.py -q`
- 合格条件：
  1. ハーネスの起動関数で起こした子が孫を起こし、子をタイムアウトで止めると、孫も一定時間内に消える
  2. ハーネスの代わりの親プロセスを `os._exit` で強制終了すると、その配下の子・孫がすべて消える（KILL_ON_JOB_CLOSE）
  3. 孫が Job から抜けようとする（CREATE_BREAKAWAY_FROM_JOB）と失敗する（BREAKAWAY_OK を付けていない）
  4. ファイルを開いたまま止まったプロセスを Job ごと閉じると、そのファイルを削除できる
  5. ハーネスのコードの中で、Job を通らない子プロセスの起動が 0 件（`subprocess.Popen`／`run` の直接の呼び出しを AST で数える。起動は 1 か所の関数に集める）

### S1-3 UUID の使い捨て作業場所

- 検証コマンド：`python -m pytest tests/test_ephemeral_sandbox.py -q`
- 合格条件：
  1. 同じタスクの作業場所を 2 回作ると、パスが異なる
  2. タスクの途中で親を強制終了し、同じタスクを再び始めると、新しいパスで始まり完了する（前回の残骸に触れない）
  3. ロックされたファイルを含む古い作業場所があっても、起動時の掃除は例外を出さず、消せるものだけ消す
  4. タスクの完了の経路に、作業場所の同期削除が無い（削除の失敗がタスクの結果に影響しない）

### S1-4 agy の固定した複製

- 検証コマンド：`python -m pytest tests/test_agy_pinned_copy.py -q`
- 合格条件：
  1. PATH の `agy` を別の版を名乗る偽物に差し替えても、ハーネスが呼ぶのは固定した複製（偽の実行ファイルが出す版で確かめる）
  2. 固定した複製の中身を 1 バイト変えると、agy を呼ぶ前に INFRA で止まる（呼ばれた回数 0）
  3. sha256 の記録が無い、または読めないときも止まる（フェイルクローズド）
  4. ハーネスのコードに、PATH から `agy` を引く呼び出しが 0 件
- 人間の作業（エージェントは実行しない）：複製のディレクトリへの ACL。手順は PR の本文に書く。

### S1-5 base 検査のホワイトリスト化

- 検証コマンド：`python -m pytest tests/test_base_whitelist.py -q`
- 合格条件：
  1. 受理のたびに、その時点で通ったテストの名前の集合をハーネスが記録する（記録はハーネスのコマンドだけが書く）
  2. 将来のタスクの、落ちるテストを注入しても、base は ABORT しない
  3. 記録された集合のうち 1 件を壊すと、base は ABORT する
  4. 記録が無い・壊れているときは ABORT する（空の集合として通さない）。最初の記録は、人間が承認したコマンドで 1 回だけ作る
  5. 除外のリスト（JSON）と、`_Hidden`・クラス単位の除外を読む経路が 0 件

## 4. 初版から残す判断と、捨てる判断

- 残す：未達のタスクはスキップ受領せず BLOCKED（Step 2 の 3）。v3.1 の M1 は縮小する（Step 3）。剪定には行数の予算を置く（Step 2 の 4）。
