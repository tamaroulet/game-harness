# B（契約駆動の防壁型）の効率：実測の検証と改善の設計

- 状態: 調査の結果と設計（コードは変えていない。実験は本走の後）
- 前提: v2-smoke-03・04（`experiments/v2/results/smoke/`）。本走の前の見直し（game-harness#96）
- 諮問（2026-09-25）: B は A に対して恒常的に時間で 1.3 倍、費用で 2 倍劣後している。原因は B の実装上の無駄（① 毎呼び出しの巨大なプロンプトによる初手の長考、② 出力の 85〜95% が思考、③ 再試行でのプロンプトの過積載、④ プレフィックスキャッシュの敗北）。プロンプトの局所化・キャッシュの最適化・反例の圧縮・思考の抑止を調べよ
- 結論:
  1. **「恒常的に劣後」は実測と合わない**。v2-smoke-03 では B が費用で 25% 安く、秒で 29% 速かった。v2-smoke-04 では B が費用 1.81 倍・秒 1.32 倍。N=1 の 2 走行で向きが逆になる。ばらつきの主因は、両条件に共通の「最初の手番の思考の長さの非決定性」
  2. **① の病因（ステートレス＋巨大なプロンプトが長考を招く）は、実測で支持されない**。A も各タスクの最初の呼び出しで同じ大きさのプロンプト（3.2 万〜4.6 万字）を受け取り、T1 は A も B も履歴が無い。v2-smoke-03 では**同じ 3.2 万字のプロンプトで A の T1 が 37,547 トークン・114.5 秒考え**、B の T5 は 2,843 トークン。長考は条件によらず出る
  3. **② は事実**。費用の最大の項は思考の出力（v2-smoke-04 の B で 57%）。ただし A も同じ（出力に占める思考は A 84%・B 91%）。**減らす価値が最も大きいのはここ**で、手段はプロンプトの設計の実験（§5）
  4. **③ の病因（過去の試行ログや冗長なエラーが積み上がる）は事実と違う**。B の再試行の知らせは反例の 1 行（最大 5 行）で、T3 の 2 回目のプロンプトは 1 回目より 1,285 字増えただけ。263,658 トークンは 2 回の呼び出しの入力の合計で、その多くは agy が 1 回の呼び出しの中で手番ごとに会話を送り直す分（2 回目は 7 手番）と、2 回目の思考 65,228 トークン
  5. **④ は事実で、原因は B のプロンプトの並びではなく agy**。B の全 6 回の呼び出しで、最初の手番のキャッシュ読みは 0。agy に**同じプロンプトを新しい会話で 3 回**渡しても、キャッシュ読みは 3 回とも 0 で、入力のトークン数が毎回わずかに違った（13,285・13,293・13,295）。agy のシステムプロンプトに呼び出しごとに変わる部分があり、**プロンプトの並びを変えても会話をまたいだプレフィックスキャッシュは効かない**。効くのは 1 回の呼び出しの中（2 手番目以降）と、会話を続ける A の履歴だけ。取り逃している額は 1 走行で約 0.11 USD（B の費用の約 10%）

## 3. B の設計として変えてよいもの・変えてはいけないもの

- **B だけの指示（DISPUTE の段落、指示の書き方）**は B の設計の一部なので、B を良くするために変えてよい。ただし A/B の比較では処置の一部として報告する
- **共有の入力**（単位定義の prompt・契約・参照データ・埋め込み・作業場所の決まり）を変えるときは、A と B に同じく当てる
- 門・性質・受入は、効率のためには変えない

## 4. 本走（V2-RUN）への影響

本走は、校正した今の形（v2-smoke-04 と同じ）のまま走らせる。ここでの改善は、本走の結果を比べる対象（v2.2 の B）として、本走の後に入れる。本走の途中で B を変えると、4 走行が同じ処置でなくなる。

## 5. 本走の後の実験と実装のロードマップ

### E1：思考の再生実験（費用の見込み 5 USD 前後）

1. 道具：実装役の呼び出しを、保存したプロンプトと作業場所の写しで N 回流す（`harness/ab/replay.py`。実装役の出力は捨て、利用量・手番・秒・編集の有無だけを残す）。正しさは、有望な腕だけ後で判定（`pipeline.judge`）に通す
2. 対象：v2-smoke-04 の B の T1・T2 の最初の呼び出し（長考が出た 2 つ）
3. 腕（各 N=8）：
   - 0：いまのプロンプト
   - 1：DISPUTE の段落を外す
   - 2：GddReference をタスクが参照するものに絞る（要求 1）
   - 3：作業場所の決まりの結びを「埋め込んだ中身で足りる。最初に編集の道具を呼ぶ」にする（要求 4。禁止ではなく手順の事実）
4. 指標：最初の手番の思考、思考の合計、呼び出しの秒、手番、編集したか。中央値と四分位で比べる
5. 判定：中央値で 3 割以上減り、編集しなかった回が増えない腕を採る

### E2：採った腕を v2.2 の B として入れ、スモーク（N=1）→ 本走と同じ形の走行（N=4）で、本走の B と比べる

- 共有の入力を変えた腕（2）を採るなら、A も同じ入力で走らせ直す
- 比べるもの：費用・秒・思考・受入・P2P・門の効果。安全性（門）は変えないので、受入と P2P が落ちないことが条件

### 見込み

- 思考が費用の 57%（B）。E1 で中央値が 3 割減れば、B の費用は約 17% 減る
- キャッシュは agy の制約で取れない（約 10% が上限として残る）
- 局所化の入力の削減は 2% 程度で、効果の中心は思考への影響（E1 の腕 2）
