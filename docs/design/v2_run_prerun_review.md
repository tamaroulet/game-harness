# 本走（V2-RUN）の前の見直し（v2-smoke-04 のログの監査の後）

- 状態: 見解・修正（記録と監視のコード）・本走の手順
- 前提: v2-smoke-04（game-harness#95）。諮問（2026-09-25）：思考の暴走と TTL、T1 の base の 116 秒、B の再試行の費用、損益分岐 N* と本走の目的
- 結論:
  1. 思考の暴走は事実で、**両条件に共通の現象**（B だけではない）。agy には思考を機械的に絞る設定が無く（`--help` の全フラグ、モデルは low・medium・high だけ）、モデルを変えると校正（スモーク）をやり直すことになる。**本走は medium のまま**、呼び出しの終わり方（思考だけの手番・error_message・agy の ERROR）を記録し、TTL の打ち切りは実装役の振る舞いとして数える
  2. T1 の base の 116 秒は、サンドボックスの最初のビルドで、**A の判定の base にも同じだけかかる**（対称）。秒の比較を歪めないので本走では変えず、base の秒を別に並べて報告する
  3. B の T3 の 263,658 トークンは 2 回の呼び出しの合計で、費用の多くは 2 回目の思考（52,009 トークン）。費用の線（30 USD・前半 15 USD）で足りる
  4. N* の回収を本走の目的にしないことに同意する。5 タスクの鎖では A の費用は伸びない（v2-smoke-04 は A の方が安い）。**本走の評価軸を「受入・P2P・不変条件・最初の提出から最終までの門の効果・費用と秒・呼び出しの終わり方」に置き直す**
  5. 見落としていたこと：**5 タスクの鎖は、v2 の主張（長期の連続でも仕様ドリフトを起こさない）を確かめるには短い**。本走（N=4）で言えるのは「5 タスクの範囲での再現性」まで

## 1. 事実（v2-smoke-02〜04 の実装役のログ。手番の型・利用量・秒・イベントの種類だけを数えた）

### 1.1 B の T3 の 2 回目の呼び出し（諮問の例）

| 手番 | 型 | 思考 | 出力 | 秒 |
|:--|:--|:--|:--|:--|
| 1 | agent_response | 13,122 | 13,122（すべて思考。道具も応答も無し） | 46.4 |
| 2 | error_message | — | — | 0 |
| 3 | agent_response | 52,009 | 52,603 | 157.9 |
| 4〜13 | 道具 5 回と短い応答 | 合計 97 | | 約 30 |

呼び出しの秒は 241.5（手番の秒の和 238.4）。諮問の数字どおり。

### 1.2 呼び出しの終わり方（3 回の走行の全呼び出し）

| 走行 | 条件 | 呼び出し | 思考だけの手番がある | error_message がある | agy の ERROR | 200 秒超 | 最長 | 出力に占める思考 |
|:--|:--|:--|:--|:--|:--|:--|:--|:--|
| v2-smoke-02 | A | 9 | 2 | 2 | 0 | 3 | 280.4 秒 | 95% |
| v2-smoke-03 | A | 13 | 1 | 2 | 2 | 6 | 279.0 秒 | 96% |
| v2-smoke-03 | B | 6（T1 の 3 回は上書きで消えた） | 0 | 0 | 0 | 3 | 272.7 秒 | 97% |
| v2-smoke-04 | A | 6 | 1 | 1 | 0 | 0 | 131.7 秒 | 84% |
| v2-smoke-04 | B | 6 | 1 | 1 | 0 | 1 | 238.4 秒 | 91% |

- 「思考だけの手番 → error_message → やり直し」は A にも B にも起きる（ステートレスかどうかと関係ない）
- agy の ERROR の 2 回は、どちらも v2-smoke-03 の A の T2。1 回は `Your previous response was cut off because it exceeded the output token limit`（出力の上限）、もう 1 回は出力が 65,532 トークン（上限の 65,536 の手前）。**思考が出力の上限に当たると、その呼び出しは編集をせずに終わりうる**
- 最長の 280.4 秒・279.0 秒は、agy の print-timeout（TTL の 20 秒前の 280 秒）に当たった可能性が高い。そのとき agy が自分で止めて result を出すので、いまの記録では普通の呼び出しと見分けられなかった

### 1.3 T1 の base

B の T1 の base は 116.1 秒（テストプロジェクトの最初のビルド。T2 以降は 9 秒）。A も判定の base（`pipeline.judge_context`）で同じビルドをする。A の T1 の秒（229.8）と B の T1（232.6）がほぼ同じなのはこのため。

### 1.4 B の T3 の費用

入力 263,658 は 2 回の呼び出しの合計（1 回目 55.2 秒・2 回目 241.5 秒）。0.5169 USD のうち、2 回目の思考 52,009 トークンの出力の費用が約 0.2 USD。
