# ADR-004 検証網と境界の再建（外側の周期を 4 周回す前の段）

- 状態：採択（2026-10-23）。裁定は実行役（Claude Code のセッション）が、操縦士の委任（「細かい判断は任せる。気にするのは抽象的な方向と進捗だけ」、2026-10-23）を受けて行った
- 台帳：ノード `rebuild`（W-18 の下）、タスク W-122〜W-140。W-61 は W-140 の後
- 前提の照合：この ADR の推奨の一部は、照合していない外部の資料に依っている。W-124 で照合し、前提が崩れた行は書き直す（§5）

## 1. 何が起きているか（要約）

段 4 の現在地 W-61 に入る前に、ハーネスを棚卸しした。結論は次の 5 点。

1. 合否を決めるのは、Gate 1 の影響テストの終了コードと、人のラベル 1 枚だけになっている。差分の意味を見る自動の層は、S2-3 で撤去されたまま、代わりの非同期の GC が作られていない
2. H ラインのテストの多くは、実装役が同じ What の中で書いている（oracle の出どころを書いた 71 件中 63 件が `from: self`）。B7.3 の役の分離は、配線されないまま外れた（コミット 1b207e0）
3. 承認と門の仕組みが、機械で強制されていない。リスクの層が無く、門のコードと CI の定義を、実装役が変えられる
4. 走らせ役（H ラインを回す常駐のループ）が Git の外にあり、外側の周期の処理が黙って落ちていた。W-61 は、これで止まっていた
5. 根は、環境と版の直書きにある。`harness/` の 120 本のうち、外部の命令の名前の直書きが 46 ファイルに 247 か所、文字コードの個別の手当てが 56 ファイルに 104 か所、OS に固有の処理が 17 ファイルに 59 か所ある。機能を抜き差しできず、環境が 1 か所変わるたびに、どこかが黙って壊れる

## 2. 決定

### 2.1 段の形

- 外側の周期（W-61・W-25）の前に、再建の段（`rebuild`）を置く。R4 の 4 周は、この段で取り直す基準の後から数える
- 再建の間、H ラインは止める（走らせ役のタスクは無効にした。2026-10-23）
- 直すのは実行役で、高い層の変更は 1 件ずつ main への PR にし、人が読む。H ラインは、自分の門・走らせ役・境界・物差しを直さない

### 2.2 裁定

| ID | 決めたこと |
|:--|:--|
| K-1 | リスクの層を、高・中・低の 3 つにする。高い層は、門・承認・保護パス・指標の計算・物差し（bench の道具とプロンプト）・CI・走らせ役・境界（ポート）・環境の台帳・層の定義そのもの。H ラインは、高い層を変える What を Gate 1 で不合格にする |
| K-2 | テストの独立性は、R4 の前に 2 段とも入れる。段階 a：テストを弱める変更の不合格・門と境界の変異・ターン切れの試行でもモデルを照合する。段階 b：受入テストを別の役が、リポジトリを探索せずに（台帳の acceptance とシグネチャだけから）先に書き、そのタスクの間は実装役が変えられないパスにする。どちらも、流れの入口から通す配線の試験を必須にする |
| K-3 | 差分の助言のレビューを入れる。新しい文脈で、別系統のモデルを使い、指摘を論破する段を 1 つ挟む。結果は統合 PR の本文に出し、合否には入れない（`tests/test_no_inline_review.py` の方針は保つ） |
| K-4 | 非劣性の基準を N=3 で取り直す。判定には、走り直しの揺れを含める。課題は足さない |
| K-5 | 非劣性の走行は、外側の束が工廠の経路（実装役への指示・Gate 1・bench の道具・計画役）に触れたときだけ起こす |
| K-6 | R4 の 4 周は、W-138（基準の取り直し）の後から数える |
| K-7 | 開いていた統合 PR（game-harness#265・game-harness#261）は、操縦士の承認（ラベル）の後に入れてから、再建に入る。エージェントは承認しない。game-harness#261 の非劣性の検査は、W-138 の取り直しが兼ねる |
| K-8 | ゲームのライン（scheduler・pipeline と v2 の契約の道具）は、消さずに凍結する。試験は別のワークフローに移し、H ラインの目次・影響テスト・カナリア・境界の作り直しの範囲から外す。再開の条件は「境界の内側に移したこと」とする |
| K-9 | H ライン専用の GitHub アカウント（machine user）を作り、承認者の一覧に入れない |
| K-10 | 走らせ役は Python に移す。起動の部分だけを、薄い型として置く |
| K-11 | 低い層の自動マージ（人の承認なし）は、R4 の前には入れない。R4 の後に、検査の実績を見て決める |
| K-12 | 再建の間、H ラインを止める。段 7（W-140）で再開する |
| K-13 | 境界（ポート）は、動いているライン（H ライン・工廠・外側の周期・走らせ役・進捗）が使うものに限る。~~ポートは、process・fs・vcs・forge・agent・host・engine の 7 つ~~ **改訂（2026-10-23）：process の 1 つだけにする。** 2026-09-01 以降の fix 49 件のうち、境界で防げたはずのものは process の 4 件だけで、ほかの 6 つに当たる不具合は 0 件だった（P-009、`docs/design/adr-004-scope-check.md`）。ほかのポートは、その境界に当たる不具合が外側の周期の 4 周の間に 2 件起きたら作る |
| K-14 | 抜き差しできることは、CI で示す。~~動いているラインの試験を Linux でも偽のアダプタで回し、~~Windows では意地の悪い環境（コードページ 932・空白と日本語を含むパス・CRLF）でも回す。**改訂（2026-10-23）：Linux のジョブは外し、リポジトリの文字の衛生の検査（BOM 無し・LF）を足す。** 環境に起因した fix 15 件と走らせ役の停止で、Linux の CI が見つけたはずのものは 0 件、BOM と改行の崩れが 5 件だった（P-010） |
| K-15 | 外部の調べものは会話に貼らず、調べ役・機械の照合（出典の URL の抜粋の照合）・反証役（別系統の小さいモデル）を通して、記録に残す。方向を決める判断は、前提の台帳の ID で根拠を引く。調べ役の CLI は設定で替えられるようにする（既定は agy の `--print --json-schema --mode plan`。代わりに Claude の小さいモデル）。利用枠が切れていれば問いを積んで待ち、照合（W-124）は枠の要らない W-125〜W-128 と並べて進める |

## 4. 物差しの不変条件との関係

`docs/prompts/director_weekly.md` は、点を決めるもの（仕様と判定役・非公開オラクル・固定の計画・実装役のモデルと版・試行の回数と TTL・Gate 1）に触れる改善を、外側の周期では置かないと定めている。この再建は、それらに触れる。そのため外側の周期の外で行い、終わってから基準を取り直す（K-6）。

## 5. 照合していない前提

次の前提は、W-124 で照合するまで「未照合」とする。崩れた前提に依る行は、この ADR を改める PR で書き直す。

| 前提 | 依る行 |
|:--|:--|
| AI のエージェントが書いた変更は、影響の大きさで承認の層を分けるのが、いま公開されている実践である | K-1・K-11 |
| LLM のレビューは、合否に入れずに、新しい文脈と別系統のモデルと論破の段で厳選すると、誤検知を減らせる | K-3 |
| 合意は正しさを意味せず、論破の段が誤報を減らす（Refute-or-Promote） | K-3・K-15 |
| Windows で、エージェントの CLI を別の OS アカウントと ACL で閉じ込める方法は、いまの実践として妥当である | 段 1（W-129） |
