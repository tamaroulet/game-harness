## 1. 諮問への見解

### 1.1 仕様の抜き出しへの依存（諮問 ①）

**半分は当たっている。** 抜き出している仕様は 2 種類で、扱いを分ける。

| 種類 | 例 | 見解 |
|:--|:--|:--|
| 参照データ（PR） | 盤面の大きさ・ミノの形・キック表・得点 | **v2 の原則に反している。** 決定 2（参照データは GDD から写す）と決定 3（誰も C# を手書きしない）と L5（データは契約の生成物）に照らすと、キック表を自然言語の表で渡して実装役に C# へ写させるのは、v1 と同じ誤りの入り口。**contractgen が GDD から読み取り専用の C# 定数として生成する**のが正しい（`properties.json` の `reference` がすでに対応を持っている）。0.3 の 1・2 はこれで消える |
| 規則（RL）と処理順（LP-07・LP-08） | 「接地して PR-03 ティック続いたら固定」 | 性質（given/then の式）が機械の正解で、規則の文章はその「なぜ」。v2 の原則は「反例で導く」だが、反例だけで仕様を当てさせると内側ループの回数が増え、思考も増える（v2-dry-04 の B は 3 ターン）。**規則の文章を渡すこと自体は後退ではない。後退なのは、どの規則を渡すかを自然言語の prompt から拾っていること**。ID の出どころを `properties.json`（そのタスクと、それまでのタスクの性質の `rule`）に変える |

### 1.2 プロンプトの肥大（諮問 ②）

- 0.2 のとおり、費用の 6〜7 割は思考。**先に打つ手は `--effort` の比較**（改善計画の裁定 3。v2.1 §6 の次の手 1 と同じ）
- プロンプトは減らすより、**キャッシュに乗せる**。埋め込みの大部分（契約・既存の型・仕様の抜き出し）は、同じタスクの中で呼び出しをまたいで変わらない。いまの B はキャッシュ読みが 69,551（A は 315,128）と少ない。プロンプトを「変わらない前置き（契約・型・参照データ・規則）→ 変わるもの（書き換えてよいファイル・反例）」の順に並べ、前置きの字面を呼び出しをまたいで同じにする
- 参照データを契約に移す（1.1）と、抜き出しは短くなる

### 1.3 禁止の指示に頼る探索の停止（諮問 ③）

**これが最大の構造的な危うさで、同意する。** v2-dry-03 で埋め込みだけでは探索が止まらず、v2-dry-04 で指示を強めて止まった。止めたのは頼みで、仕組みではない。

- 改善計画 §1.1 の 5（**作業場所を細くする**。v2.2 に置いていた）を v2.1c に前倒しする。書き換えてよいファイル・契約・既存の型だけを置いた一時ディレクトリで実装役を動かし、終わったらハーネスが書き戻す。置いていないものは読めない
- 実装役は編集だけで、ビルドもテストもしない（v2 §7）ので、Unity のプロジェクトが無くても仕事はできる
- 同じ作業場所を A・B の両方に当てる（改善計画 §1.1 の公平性）。**A に何を置くかは裁定が要る**（§4 の 2）
- 指示（「読まない」）は残す。作業場所が細くなれば、指示は守れない場合の保険ではなくなるので、そのうち消せる
- テレメトリは、作業場所の外を読もうとした手番（道具の失敗）を数え続ける

### 1.4 T2〜T5 への汎用性（諮問 ④）

**T5 では、いまの抜き出しは確実に壊れる**（0.3 の 1）。形のデータ（0.3 の 2）も未確認。静的に確かめる検査を足し、それを通ってからスモークに進む（§3 の 4）。

## 4. 裁定が要ること

### 5.3 見解と次に決めること

細い作業場所は目的（テストと仕様書を読ませない）を仕組みで果たした。一方、手番の数は、頼みを外すと戻ることが実測で分かった。手番の大半は作業の管理と端末の操作で、費用は思考が減った分だけ下がっている。**ただし B の実装役の 1 回は 270.3 秒で、TTL（300 秒）の 9 割に達した。** T2 以降は書き換えてよいファイルが育つので、このままスモークに進むと TTL の打ち切り（L4 の再演）が出る見込みが高い。

裁定が要ること：

1. **手番の空回りをどう扱うか**。
   - (a) 受け入れて V2-6 に進む：費用は v2-dry-04 より低い。TTL の打ち切りが出たら止める
   - (b) 事実だけを書き足す：「作業場所にあるのは埋め込んだファイルだけで、作業の管理は要りません」。禁止ではないが、言葉で導くことには変わらない（ADR の原則から外れる）

2. **V2-5 の complete の時期**。基準は満たしたが、この PR（コードと単位定義）が main に入ってから complete する。V2-6 は main の版で走らせる
