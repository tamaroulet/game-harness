# V2-6：T5 の受入の修正（公開シード 30 本と、前提の探索）

- 状態: 実装済み
- 前提: game-harness#86 §4（T5 のキックの性質が、公開シード 5 本では正しい実装でも前提が 1 度も成り立たない見込み）。2026-09-25 の裁定：公開シード 30 本＋生成の時点の前提の検査
- 区分: 受入の定義（性質の宣言と性質テストの生成器）を変える。単独の PR

## 1. 変えたこと

| # | 内容 | 場所 |
|:--|:--|:--|
| 1 | 公開シードを 5 → 30 本 | `experiments/v2/properties.json` |
| 2 | **前提の探索（Directed）**：性質ごとに、given を `&&` で分け、`input.X`・`!input.X` を最初の手の入力に、開始状態だけで評価できるもの（`before.Phase`・`before.ActiveMino`、`fits`・`kick` など after を使わない関数）を前提にする。開始状態の材料（盤面・ミノ）を実装を使わずに作り、前提が成り立つシードを決定論で探して、その系列を最大 3 本、公開・非公開のシードの系列に足す | `harness/propgen.py`（`directed`、生成物の `PropertyRunner.Directed`・`Checks.Pre_*`・`Checks.First_*`） |
| 3 | **前提の検査**：実装を動かす前に探索を行い、前提が成り立つ系列が 1 本も無ければ `PROPERTY_UNSATISFIABLE id=… rule=… searched=N` で落とす。これは実装に依らない（宣言か生成器の欠陥）。宣言の検査（`validate`）は、最初の手の入力が真と偽の両方を求める宣言を拒む | 同上 |
| 4 | `PROPERTY_UNSATISFIABLE` を、反例の行として実装役と記録に届く行に足す | `harness/adapters/dotnet.py` |

「生成の時点の検査」は、C# の乱数と開始状態を Python で写さずに済むよう、生成したテストが**実装を動かす前**に行う形にした。探索は開始状態の材料（ハーネスの生成器）と参照モデルだけを使い、実装のコードを一切呼ばない。

## 2. 確かめたこと

生成した参照モデルと判定（`PropertyModel.cs`・`Checks.cs`）と契約を、スクラッチのプロジェクト（net8.0、NUnit 3.14.0 はローカルのキャッシュから）で、実装の代わりの空の `GameState`（Tick は呼ばない）とともにビルドし、全 20 の性質で探索を走らせた（生成物の中身は見ていない）。

| 性質 | 見つかった系列 | 試したシード |
|:--|:--|:--|
| P-T1-01〜04 | 3・3・3・3 | 5・3・8・3 |
| P-T2-01〜04 | 3・3・3・3 | 3・3・3・3 |
| P-T3-01〜04 | 3・3・3・3 | 3・52・3・3 |
| P-T4-01〜04 | 3・3・3・3 | 20・20・3・5 |
| P-T5-01〜04 | 3・3・3・3 | 6・236・7・21 |

すべての性質で、開始状態の前提と最初の手が成り立つ系列が 3 本見つかった（上限 20,000）。after を使う前提（固定ブロックが増えない、など）は、正しい実装なら成り立つ。

## 3. 影響

- 公開シードが 6 倍、探索の系列が 3 本増えるので、性質テストの実行時間は伸びる
- 探索の系列は決定論なので、実質は公開の系列。反例は実装役に届く
- 非公開シードの本数（門 20・測定器 20）は変えていない
- スモークの止める条件（`v2_6_smoke_plan.md` §3.1）に `PROPERTY_UNSATISFIABLE` を足す（ハーネスの欠陥）
