- SWE-Chain（`1cd84f09e41d`。最も重い pytest 8 の 8.2.2→8.3.0→8.3.2→8.3.3 と、attrs の 21.4.0→22.1.0→22.2.0→23.1.0）：
  - L2 は通過。手元で作り直した oracle は、2 区間・14 ファイルで公開の oracle と全項目一致（upgrade-related の集合も一致）。L4 も通過（メモリの最大 1.97 GB、残ったコンテナとプロセス 0）。
  - 欠陥 1：公式の差分の当て方（`git apply`）は、リポジトリの中の一時のフォルダで走るので、README のとおり git clone した中では 188 ファイルのパッチをすべて飛ばして終わりの符号 0 を返す。採点はどのステップも始まりのコードのまま行われ、正解でも resolving 0% だった。同じコミットの git の外のコピーでは当たる。
  - 欠陥 2：公式の採点は自前の pytest のプラグイン（`__import__` を差し替える）を入れて走らせ、正解の版の基準のテストはそれ無しで走る。pytest の自己テストの 3 項目が採点の条件では必ず落ち、毎ステップ upgrade-related に数えられる。git の外での正解の再生は、pytest 8 で resolving 96.8%・40.0%・57.1%（regressed 0）、attrs で 3 ステップとも 100%。同じ項目が鎖の半分以上のステップで upgrade-related になる目印は、12 鎖のうち 6 鎖にあった（flask で upgrade-related の 45%、pytest 7 で 18%、pytest 8 で 10%、xarray の 2 鎖で 11%・8%、conan 2.12 で 3%）。
