# 憲章（v4 の第 1 層）

- 状態：2026-11-13 に操縦士が決めた。変えるのは操縦士だけ。
- この文書には目的・制約・変えない条件だけを書く。手段（モデルの名前・道具・課題の種類・ハーネスの形）は書かない。手段は第 2 層（[設計と仮説](design.md)）、実験は第 3 層（[実験と計画](experiments.md)）に書く。

## 1. 目的

1. 人はゲームの創作の上流に専念する。企画・世界観・設計の大枠・創作の判断・安全の境界・方向の決めが人の仕事で、下の層の実装と検証は任せる。
2. そのために、実戦のゲーム開発に繋がる、ROI の高い自律開発の環境を作る。ROI は、時間・利用枠・手戻りの防止で見る。
3. 素のチャットのエージェントと公平に比べて、どこまで素のチャットで足り、どこからハーネスが効くか（損益分岐点）を突き止める。勝つこと自体は目的にしない。
4. 結果を、第三者が公開のリポジトリで読んで確かめられる資料にする。研究の成果として、作品と並べて示せる形にする。

## 2. 実戦の想定

- 実戦では、その時点で最も賢いモデルに、中くらいの単位の仕事（1 つの機能・1 つのまとまり）を一括で任せる。
- 弱いモデルが迷わないように仕事を細かく刻み、そのたびに文脈を消して面倒を見る形は採らない。
- 検証のために安いモデルを使うことはあるが、それは仕組みの効き目を確かめるための仮の選択で、実戦の前提にしない。
- ハーネスの役目は、中くらいの仕事の入口（何をもって完了かを先に決める）・内部（賢いモデルに一気に走り切らせる）・出口（決まった検証で未完成と退行を押し返し、合格したものだけを確定して次へ引き継ぐ）を受け持つこと。

## 3. 制約

- 1 人で、個人の定額の利用枠（Claude と Gemini）の中で回す。学術論文並みの過剰な繰り返しも、確かめの省略もしない。結果で次の決めが変わらない実験はしない。
- 車輪の再発明をしない。公開されている評価の基盤や先人の知見を先に調べ、使えるものを使う。
- 秘密（API キー・トークン・パスワード）を探さない・使わない・公開しない。held-out の課題の中身と、非公開の課題の中身は公開に書かない。

## 4. 出口（3 つとも満たす）

1. 基盤：実戦に持っていける、ROI の高い仕組み。
2. 公平な比べ：無駄を削り切った後の比べと、損益分岐点。負けた所と限界も書く。
3. 公開資料：第三者が読んで確かめられる形（手順・数・限界・再現の仕方）。

## 5. 比べの公平の原則

- 素のチャット（A）は、人が使うのと同じく、1 つの会話を続ける形で、ハーネスの儀式も注意書きも足さない。
- 両方で同じにするのは、課題・モデルと思考の強さ・環境・上限（時間と利用枠）・採点。
- 頼みの文面でモデルにお願いする調整は、効きに数えない。効きに数えるのは、外から変え・足し・削れる仕組みだけ。
- 共通の無駄も削る対象にし、削った後の同じ設定で揃える。
- 開発用の課題は探索に、held-out の課題は証明に使う。公開の主張は held-out で確かめたものだけ。結果を見てから課題を作り直さない。測る物差しと判定の線は、走らせる前に書く。
- 素の A が一度も落ちない課題では、ハーネスの価値は測れない。課題は、A が実際に落ちることを先に確かめてから使う。

## 6. 人が決めること

- 方向と計画の変更、外に出る操作（公開・PR のマージ）、戻せない操作、利用枠を大きく使う実行。
- 創作の判断（好み・世界観・遊びの手触り）と、何をもって完了とするかの受け入れの基準。
