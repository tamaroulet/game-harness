  - API の値段での換算：約 0.32 ドル（キャッシュでない入力 0.127・出力 0.136・キャッシュの読み 0.055）。同じトークンを 3.8 Flash の値段に当てると、2026 年の値段で 0.19 ドル、2027 年の値段で 0.37 ドル（Flash の実測ではない。単価の差だけを見る数）。

  - 失敗の型：F2P の落ち 16 件のうち 10 件は、課題の文に書かれていない部品（ECDF と LetterValues の内部の関数）。隠された部品の少なくとも 1 つ（ECDF の _eval_univariate）は、残ったコードから呼ばれていた → 呼び先の無い参照を確かめずに終えた（手順の型。出口の型・参照の検査が狙う落ち方）。同時に、課題の文の書き落とし（ベンチの不備）でもある。3 件は Histogram の binwidth の扱いの誤り（読み違いか細部の力の不足）、3 件はほか（分けていない）。
  - agy は、正解のテストのファイルが消されているので既存の別のテストだけで確かめ、課題の文に書かれた 2 つの部品（KDE・Histogram）を作って「できた」と答えて終えた（早合点）。
  - 0-b の残り：本物の agy は /testbed に自分のファイルを残さなかった（パッチは seaborn/_statistics.py だけ）。OAuth の更新は 3 つの宛先で通り、トークンの漏れは無かった（fb_agy check で合格）。

## 4. X-02 開発（部品を 1 つずつ）

- 目的：仮説 H2〜H5。共通骨格の 3 つ（入口の要件の台帳・1 つの単位を 1 つの会話で続ける・出口の機械の背圧＝既存のテストの回帰と型・参照・静的解析）を、1 つずつ足し、外して確かめる（[設計と仮説](design.md)の §4-2）。正解の受け入れテストは使わない（ベンチの通常の実行では隠されている）。H5 は、効きが共通骨格から出るか（細かいリセットや独立の検証役を足さないと出ない形でないか）を見る。

## 5. X-03 証明（封をした held-out）
