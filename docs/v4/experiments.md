### M-01 agy の新しい会話のキャッシュの立ち上がり（2026-11-13）

- 材料：箱の中の実装役（agy 1.5.3、gemini-3.8-flash-medium）の stream-json の記録。3 本のラン（A の会話の形の 1 ステージ目 1 回、B の 6 ステージ、前の A の 18 ステージ）で、新しい会話の始まりが計 25 回。
- 読み方：応答ごとの `cache_read_tokens` と `input_tokens`。キャッシュの読みが 0 でなくなる最初の応答と、その手前の文脈の長さ（入力＋キャッシュの読み）を見た。
- 結果：
  - 25 回とも、最初の 5〜12 応答はキャッシュの読みが 0。当たり始めるのは、手前の文脈が約 1.6 万〜2.1 万トークンを越えた所（最初の当たりの読みは 1.5 万〜2.1 万。1 回だけ 4,681 で当たり、次の応答で 0 に戻った）。

  - 会話を続けた A は、2 ステージ目以降、最初の応答から前の会話のキャッシュに当たった（読み 63,654 → 183,605）。
- 公開の文書との差：Gemini API の文書は、3.8 Flash の implicit caching の最低を 4,096 トークンとする。agy の経路はこれと合わない。仕組みは公開されていないので、実測で扱う。

### 5-2. 公式のテストの項目の根拠の分け（静的な規則。パッチの結果を見ずに、走らせる前に決めた）

- 使うもの：課題の文・隠しのパッチ（データの patch。実装を消すパッチ）・公式のテストのファイル（データの test_patch から戻した元の中身）・課題の始まりの状態（隠しのパッチを当てた後）のソース（テストのファイルを除く）。A のパッチと、評価の結果は使わない。

- 規則：
  1. 消された名：隠しのパッチが消した行（テストのファイルを除く）の、`def 名`・`async def 名`・`class 名` と、字下げの無い代入 `名 =` の名。前後が `__` の名は除く。
  2. テストの範囲：公式のテストのファイルのテストの関数ごとに、関数の本体・同じクラスの準備のメソッド（setup_method・setup_class・setup・setUp）・引数の名と同じ名の、同じファイルの fixture の本体・本体から名で直に呼ぶ、同じファイルの関数の本体（1 段まで）。

  4. 範囲の中の文言：
     - match= の文字列：pytest.raises・pytest.warns・pytest.deprecated_call と、名が assert_produces_warning の呼び出し。

### 5-5. 第 2 関門の仕様（E-1 での形。設計 §4-2）

- 入力（検証役に渡すもの）：
  - 課題の文（要件の台帳に当たる。全文）。
  - 課題の始まりの状態のリポジトリ（隠しのパッチを当て、公式のテストのファイルを消した状態。実装の前のコードと既存のテスト）。

- 出力：決まった置き場の pytest のファイル 1 つ。テストの関数ごとに、docstring の決まった形で、確かめる課題の文の項目と、期待する値の根拠になる課題の文の引用を書く。引用は、課題の文に一字一句あるもの。
- 走らせ方：
  - 課題ごとに 1 回、新しい agy の会話（gemini-4-hydrogen-medium、P-032）で作る。箱の網は agy の宛先だけを通す。
  - 始まりの状態の箱の中で、検証役は自分のテストを走らせてよい。実装が無いので落ちるが、名前と引数の誤りには気づける。
  - 作ったファイルは箱の外に写して固める（SHA-256 を記録）。候補（正解・A のパッチ）ごとに、候補の状態の箱でハーネスが走らせる。当て直しはトークン 0。
- 押し返す力の分け（静的。作った後、走らせる前に機械で決める）：

  - 引用が課題の文に無い関数も「知らせるだけ」。
  - ほかは「押し返す」。
- 誤った実装の追認を防ぐ仕組み：検証役は候補の実装を見ない。期待する値は、候補の状態で走らせる前に固める。候補ごとに作り直さない。

#### 第 1 関門の基準（操縦士の決め、2026-11-17）

- 段 a の読み（正解の状態の検出を基準の代わりにした差）は、比較条件の中では使わない。正解との差で読むと、t=0（実装を消し、公式のテストのファイルを消した始まりの状態）の検出のうち、どれを押し返すかを正解で選ぶことになり、押し返しの文に正解から得た情報が入るため（設計 §4-2）。
- 比較条件の中の読みは、下の R0 にする。正解・隠しのパッチ・消した公式のテストの一覧は使わない。正解は、R0 が正しい実装を押し返さないかの測定と、採点にだけ使う。

#### R0 の規則（G0-3 の集計の前に書いた。集計の後は変えない）

1. 静的な検査（harness/fb_gate_probe.py の未定義の名前・import・属性）：t=0 に無かった検出だけを押し返す。比べる鍵は、未定義の名前が（ファイル・種類・名前）、import が（モジュール・誤りの種類）、属性が（ファイル・クラス・属性の名前）で、行番号は使わない（harness/fb_replay.py の keysets と同じ）。パッケージの外のモジュールが無いことによる import の誤りは数えない。
2. テストの選び方（-k などで絞らない）：
   - 群 1：候補が足したか変えたテストのファイル（名前が test_ で始まるもの）。
   - 群 2：台帳の Path（課題の文の Interface の Path）のモジュールを import する、t=0 にあるテストのファイル。
   - 群 3：候補が変えたソース（テストのファイルを除く）のモジュールを import する、t=0 にあるテストのファイル。
   - モジュールの名のうち最上位のもの（`.` を含まない名。例 `pandas`）は、群 2・3 の選びに使わない。最上位の `__init__.py` が変わると、ほぼすべてのテストのファイルが当たる（run3 の正解の状態で、pandas の 2 課題が 891〜897 ファイルを選び、課題と関係の無い pandas/tests/api/test_api.py まで入った）。最上位のパッケージの import の壊れは、1 の import の検査が拾う。
   - 走らせる順は群 1 → 群 2 → 群 3 で、群の中はパスの順。1 つのファイルは、最初に当たった群にだけ入れる。
3. テストの時間（1 回の関門）：
   - test_budget：テストの段の全体で 300 秒。残りが 0 になったら、後のファイルは走らせず「走らせなかった」と残す。
   - file_timeout：1 ファイルの上限。300 秒と、test_budget の残りの短いほう。この上限で止めたファイルは項目の結果が出ないので、そのファイルの項目はすべて不明とする（落ちに数えない）。
   - timeout_one：1 項目の上限。課題の設定のまま（pytest-timeout）。
4. 押し返すテストの落ち：走らせた項目の FAILED・ERROR のうち、誤りの文が次の環境の型（E1〜E6）に当たらず、判別できないもの（U）でもないもの。
   - E1 ネットワークの遮断と、外部のデータの取得・更新の失敗：誤りの文に `URLError`・`urlopen error`・`Name or service not known`・`Temporary failure in name resolution`・`Network is unreachable`・`Connection refused`・`ConnectionError`・`Max retries exceeded`・`gaierror`・`auto-update failed`・`is expired` のどれかがある（run3 の正解の状態の例：astropy の leap-second のファイルの期限切れと自動更新の失敗）。
   - E2 パッケージの外のモジュールの欠け：`No module named 'X'` で、X の最上位の名が対象のパッケージ（課題の設定の library_name）でない（例：pyspark・IPython、sphinx のテスト用の fish_licence.halibut）。
   - E3 パッケージの外の依存の版のずれ：`module 'X' has no attribute` か `cannot import name '…' from 'X'` で、X の最上位の名が対象のパッケージでない（例：moto の mock_s3）。
   - E4 リポジトリの外の状態の欠け：`FileNotFoundError`・`NotADirectoryError`・`IsADirectoryError`・`PermissionError` で、誤りの文の絶対パスがリポジトリの根（/testbed）の外にある（例：/root/.mlflow/envs）。
   - E5 外部コマンドの欠けと失敗：誤りの文に `exited with return code` か `command not found` がある（例：lualatex・xelatex）。
   - E6 1 項目の時間切れ：`Timeout (>…s) from pytest-timeout`。
   - U 判別できないもの：誤りの文が空の落ち。run3 では、収集の誤り（終わりの符号 2 のファイル）がこれになる。JUnit XML の収集の誤りの本文を項目に結び付けられず、空になった。
   - 対象のパッケージの名に当たる `No module named`・`module '…' has no attribute`・`cannot import name … from` は、環境の型にしない（消された部品の穴として押し返す）。
5. テストの改変：t=0 で git が追うテストのファイルを、候補が変えるか消したら押し返す（import の行だけを許す例外は無い）。新しく足したテストのファイルは、改変に数えない。
6. 1 つの状態で、1・4・5 のどれかが 1 つ以上あれば「押し返す」。
