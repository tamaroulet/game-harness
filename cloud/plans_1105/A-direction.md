# 頼み A：方向と費用対効果の監査（頼みの名：A-direction）

先に `cloud/plans_1105/common.md` を読み、その決まりに従う。書く文書は `docs/design/cloud_1105/A-direction.md`。

## 問い

1. このリポジトリの元のねらい（総監督の木・立て直しの文書・ADR から読み取れるもの）を、あなたの言葉で 5 行以内に書く。読み取れないところは、読み取れないと書く。
2. v3 の計画（線 1：MuJoCo の累積の鎖で外側の周期を確立する → 線 2 → L6〜L8）は、そのねらいへの道として妥当か。最短か。費用（トークン・人の手・日数）に見合うか。§15 の L1〜L5 の実測と照らして答える。
3. 計画が見落としている根本の問い・置いたままの前提はあるか。たとえば：物差し（鎖）で測れる改善が、ねらいの側（実戦の接続先）で効くと言える根拠。いまの実装役（コマンドを走らせられない Flash）を前提にした周期の価値。人の手が要る所がどこに残るか。
4. L6 を始めると、それより後は環境（走らせ役・物差し・面）を変えない。その前提で、L6 を始める前に変えるべきことはあるか。あれば、最小の変更と、それをしない場合の損を書く。無ければ、無いと言える理由を書く。
5. 代案を 2〜3 個（今の計画をそのまま続ける案を含む）、損得と費用と戻しにくさつきで並べ、推す案を 1 つ出す。

## 気をつけること

- 計画の書き手（会話の席）も Claude なので、同じ盲点を持ちうる。計画の文章の言い分をなぞらず、実測（§15・公開の集計・コード）から組み立て直す。
- 批評役の 1 つは、「この計画を止めるべきだ」という立場で書かせる。
