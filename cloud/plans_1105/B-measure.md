# 頼み B：物差しと守りの監査（頼みの名：B-measure）

先に `cloud/plans_1105/common.md` を読み、その決まりに従う。書く文書は `docs/design/cloud_1105/B-measure.md`。

## 問い

1. L6 の取り込みの判定（`docs/design/l6_approval_v3.md` §3：狙いの段の対の走り・開発の組と保留の組の回帰の守り・費用の判定。保留の組の判定は 11-05 に試験の数を併せた）は、揺れの下で正しく取り込みを決められるか。
   - 揺れの手がかり：開発の組の同じ版（v0）の 2 回で、通った段が 13 と 16（`bench/records/chains/v0-r1`・`v0-r2`、v3 §15）。保留の組は 1 回で 12（合計だけ）。
   - 本当に効く改善を捨てる見込みと、効かない（または悪くする）改善を取り込む見込みを、公開の数から見積もる。見積もりの置いた前提を書く。
2. 狙いの段の対の走り（基準の 2 回のそれぞれの段 k−1 の先端から 1 対ずつ）の組み方に、偏りや穴はあるか。鎖は巻き戻さないので、前の段の揺れが後の段に連なる（v3 §15 の L2′ の読み）。
3. 合わせ込みの守り（保留の組は 1 周で 1 回、提案役には合計だけ）と、漏れの守り（面の差分の検査・道の検め・読む根）に穴はあるか。コードで確かめて書く（`harness/surface.py`・`harness/proposer_launch.py`・`harness/chain_score.py`・`harness/bench_guard.py` など）。
4. 段の上限（時間 1 時間・300 万トークン）が比べを歪める所はあるか。v3 §15 の 11-05 の項（時間の上限で止まった段・門の試験の走り直し）を読む。
5. L6 の前に変えるべき最小のことと、L6 の中で記録しておくべきこと（後の周で判定を直すため）を分けて書く。L6 を始めると物差しを変えない前提で答える。

## 気をつけること

- 数の見積もりは、手で計算するか、小さな Python で確かめる（そのコードは文書に貼るだけで、リポジトリに足さない）。
- 批評役の 1 つは統計の観点、1 つは「守りを破る側」の観点にする。
