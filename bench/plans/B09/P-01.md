# play の入口・入力検査・パドル
マイルストーン: bench
タスク: P-01
要件: REQ-01, REQ-02, REQ-03, REQ-04, REQ-07, REQ-08

## What
- リポジトリの根の `catcher` パッケージが `play(seed, controller, steps)` を公開する。返り値は辞書で、キーは `caught`（int）・`missed`（int）・`events`（list）・`paddle`（長さ `steps` の float の list。k 番目は k＋1 歩目の後の p）。この段では玉の判定はまだ無く、`caught`・`missed` は 0、`events` は空の list でよい
- `controller(state)` は各歩の前に 1 回、k＝1 から `steps` まで順に呼ばれる。`state` は辞書で、`step`（int）・`paddle`（float）・`balls`（長さ 10 の list）を持つ。`balls` の各要素は `x`・`z`・`vz`・`resolved`・`caught` のキーを持つ辞書。この段の値は、`x` が仕様の x_i、`z` が 1.0、`vz` が 0.0、`resolved` が False、`caught` が None
- `controller` が返した値は、仕様の式でパドルを動かす。切り詰めは [−1, 1] と [−0.5, 0.5] の両方で、端の値はそのまま通る
- 入力の検査：`seed` は 0 以上 2³² 未満の int、`steps` は 1 以上 5000 以下の int、`controller` は呼び出せるもの。`bool`・float・文字列・範囲外・呼び出せない `controller` は `ValueError`。`controller` の返り値が `bool`・`None`・NaN・無限大・数でないものなら、`play` が `ValueError` を投げる
- `controller` に渡す `state` は写しである。`controller` が `state` やその中の list・辞書を書き換えても、パドルの動きと返り値は変わらない
- 同じ `seed` と同じ `controller` で 2 回呼ぶと、返り値のすべての値がビット単位で一致する

## 合格条件
- 変えるファイルは `catcher/__init__.py` と `tests/test_catcher_play.py`
- 試験は、入力の検査（各種の不正な値）、パドルの切り詰め（速さ・位置の両方）、`state` の書き換えに影響されないこと、2 回の呼び出しの一致、`x` が `random.Random(seed)` から求めた値と 1e-12 以内で一致することを確かめる
- 試験のモジュール名は `tests.test_catcher_play`
