# 玉の落下と一度だけの判定
マイルストーン: bench
タスク: P-02
要件: REQ-05, REQ-06

## What
- `play` の `state["balls"][i]` の `z`・`vz` が、止まって保たれる間は 1.0 と 0.0、落ち始めて j 歩目の後は z ＝ 1 − 9.81·0.002²·j·(j＋1)/2、vz ＝ −9.81·0.002·j と 1e-9 以内で一致する。i 番の玉は 375·i 歩目まで止まり、375·i ＋ 1 歩目から落ちる
- i 番の玉の判定は 375·i ＋ 226 歩目に一度だけ行い、その歩の後のパドルの中心 p について |x_i − p| ≤ 0.1 なら受けた（`caught` が True）、そうでなければ落とした。端の値（差がちょうど 0.1）は受けた側
- `play` の返り値の `events` は、`steps` 歩までに判定の歩が来た玉のすべてを、ちょうど一度ずつ、判定の歩の順に持つ。各要素は `ball`（int）・`step`（int）・`caught`（bool）の辞書。返り値の `caught` は真の事象の数、`missed` は偽の事象の数で、合計は `events` の長さ
- `state` の `resolved`・`caught` は、判定の歩の後の呼び出しから、その判定を表す（判定の前は False と None）。判定の歩そのものを処理する前の呼び出しでは、まだ判定済みではない

## 合格条件
- 変えるファイルは `catcher/__init__.py` と `tests/test_catcher_fall.py`
- 試験は、z・vz が式と一致すること、`events` の件数・順・歩（375·i ＋ 226）、`steps` が判定の歩の前後（225・226 など）で `events` の長さが変わること、`resolved`・`caught` の変わる呼び出しの位置を確かめる
- 試験のモジュール名は `tests.test_catcher_fall`
