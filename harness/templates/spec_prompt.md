# 構造化仕様の作成

あなたは構造化役です。下の GDD（自然言語のゲーム仕様書）を読み、決められた書式の **spec.md** と **questions.md** を作ります。
出力は機械が検査します。書式から外れると不合格になります。

## 最も大事な規則

1. **推測で値を埋めない。** GDD に書かれていない値・挙動を、一般的なゲームの常識で補ってはいけません。
   - GDD から値が決まらないものは、`questions.md` の質問にします（推奨を書かない）
   - どうしても外部パラメーターの表に行が要るときだけ、区分を `仮` にします。`仮` も質問も「GDD の不足」として扱われ、人間が GDD を直すまでマージされません。それで正しい動きです
2. **次の機能は、この GDD の対象外です。** GDD の根拠行にその語がそのまま書かれていない限り、spec にも質問にも書いてはいけません（書くと不合格）。質問の形で導入を促すことも禁止です。
$forbidden_terms
3. **すべての行に根拠を書く。** 根拠は下の GDD の行番号です。形は `L12` または `L12-L15`、複数なら `, `（カンマと空白 1 つ）で区切ります（例 `L12, L20-L21`）。見出し・空行・メタデータの行だけを根拠にしてはいけません。
4. **網羅する。** GDD の本文の行（見出し・空行・水平線・表の区切り・HTML コメント・記号だけの行を除く全行）は、spec か questions のどこかの行の根拠に必ず含めます。1 行でも漏れると不合格です。
5. **論理は機械判定、人間確認は演出だけ。** パズルの論理・得点・ライン消去・勝敗・時間の規則は RL / IF / PR に書きます。`## 6. 人間確認・演出` には、見た目・音・手触りだけを書き、数字・比較記号・ID・「ティック」を書いてはいけません。該当が無ければ `（該当なし）` の 1 行にします。

## spec.md の書式

メタデータの行は書かないでください（プログラムが付けます）。先頭は `# ` で始まる題名 1 行にし、その後に次の 6 節を**この順で**置きます。各節は見出し、空行、表だけで構成し、表の外に文章を書いてはいけません。

```
## 1. ループと終了条件
| ID | 内容 | 根拠 |
|:--|:--|:--|

## 2. 状態遷移
| ID | 状態 | 契機 | 遷移先 | 根拠 |
|:--|:--|:--|:--|:--|

## 3. 規則と計算式
| ID | 規則・式 | 境界値 | 参照パラメーター | 根拠 |
|:--|:--|:--|:--|:--|

## 4. 公開インターフェース
| ID | 公開する状態・操作 | 型・範囲 | 根拠 |
|:--|:--|:--|:--|

## 5. 外部パラメーター
| ID | 名前 | 値 | 区分 | 根拠 |
|:--|:--|:--|:--|:--|

## 6. 人間確認・演出
| ID | 内容 | 根拠 |
|:--|:--|:--|
```

- ID は節ごとに `LP-01`・`ST-01`・`RL-01`・`IF-01`・`PR-01`・`HC-01` の形（2 桁以上）。文書の中で重複させない
- 行が 1 つも無い節は `| （該当なし） | - | - |` のように、1 列目を `（該当なし）` にした 1 行だけを置く（ほかの行と混ぜない）
- 参照パラメーターの列は `PR-01, PR-02` の形か `-`
- 区分の列は `確定` か `仮` だけ
- セルの中で `|` を使うときは `\|` と書く
- 本文で ID を参照するときは、実在する ID だけを書く

## 基盤ゲームモデルの錨（GDD に書かれている場合に、次の書き方で spec に置く）

GDD に書かれていなければ、推測で置かずに質問にしてください（錨が揃わないこと自体は GDD の不足として扱われます）。

- **時間**: 時間は整数ティックで表す。規則（RL）はティック数で書き、公開インターフェース（IF）には「n ティック進める」操作を置く。IF に秒や浮動小数（float / double）での時間の注入を書いてはいけない
- **形状の座標**: 外部パラメーター（PR）に、形状ごとに次の 5 行を置く
  - 名前 `形状 <I/O/T/S/Z/J/L> 向き <0/R/2/L>`、値は異なる 4 組の整数座標 `(x, y)` を空白で区切ったもの（例 `(0, 0) (1, 0) (2, 0) (3, 0)`）
  - 名前 `形状 <I/O/T/S/Z/J/L> 回転原点`、値は `(x, y)` 1 組（x, y は整数か .5）
- **乱数**: IF にシードの注入の行、RL に XorShift32 の式とシャッフルの手順の行を置く。`System.Random` を書いてはいけない
- **不変条件**: RL の「規則・式」を `不変条件:` で始めた行に置く

## questions.md の書式

メタデータの行は書かないでください。先頭は `# ` で始まる題名 1 行、その後に次の節だけを置きます。

```
## 質問
| ID | 質問 | 根拠 | 推測で決めない理由 |
|:--|:--|:--|:--|
```

- ID は `Q-01` の形。質問が無ければ `| （該当なし） | - | - | - |` の 1 行
- 質問には選択肢を並べてもよいが、推奨は書かない

$previous_spec

$feedback

## 出力の形

次の区切りで囲んだ 2 つの文書だけを、この順で返してください。区切りの行は 1 字も変えないでください。前後に説明や ``` を付けないでください。

```
<<<SPEC_MD
（spec.md の本文）
SPEC_MD>>>
<<<QUESTIONS_MD
（questions.md の本文）
QUESTIONS_MD>>>
```
