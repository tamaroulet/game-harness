## 4. 実験の条件と境界

### 4.1 情報の対称化（A と B に同じものを渡している点）

| 項目 | A | B |
|:--|:--|:--|
| 単位定義の prompt（性質・前のタスクの性質・式の読み方・全タスク共通） | 同じ | 同じ |
| interface（型とメンバー） | 同じ | 同じ |
| 契約・既存の型・書き換えてよいファイルの中身の埋め込み | 同じ（各タスクの最初の呼び出しだけ） | 同じ（毎回の呼び出し） |
| 作業場所の決まり（`tool_policy`） | 同じ（末尾） | 同じ（末尾） |
| 作業場所 | 細い作業場所（書き換えてよいファイルと契約と既存の型だけ。テストは置かない） | 同じ |
| 受入テスト | **渡していない**（両条件とも作業場所に無い） | 渡していない |
| 検査と知らせ | B と同じ判定（`pipeline.judge`）の知らせ（反例の 1 行など）を再試行に入れる（game-harness#89） | pipeline の門（内側ループ・whitelist・静的検査・性質テスト・不変条件） |
| 呼び出しの上限 | 9 | 9 |
| 最初の提出の測定 | 同じ測定器・同じ非公開シード（実装役には知らせない。game-harness#90） | 同じ |
| 会話 | 続ける（`--conversation`。前のタスクの会話を持つ） | 呼び出しごとに新しい会話 |
| 固有の文面 | 「あなたは落ちものパズル falling-blocks の実装者です」の 1 行、`# タスク <ID>` | 作業場所の 1 行 |

- **受入テストはどちらの条件にも渡していない**。渡しているのは受入の中身である性質の宣言（前提と帰結）と、型の定義（interface と契約のファイル）
- 条件の差は、会話を積むか（A）、毎回ゼロから契約と性質だけで始めるか（B）の 1 点に寄せてある

### 4.2 測定の限界

1. **規模**：5 タスク。A の入力の傾きの中央値は 1.055 で、会話の累積による破綻（忘却・先祖返り・文脈の上限）は現れていない。長期の優位（B の存在理由）は、この本走では測れていない
2. **門が働く場面が無かった**：40 タスクすべてが 1 回の呼び出しで通り、最初の提出も合格した。B の門の効果（最初の提出 → 最終）と、A の再試行での会話の効き方は、V2-RUN では観測されていない
3. **N = 4**：四分位は 4 点から。実装役の思考は同じプロンプトでも揺れる（v2-smoke-03 で A の T1 の最初の手番が 37,547、`docs/design/v2_b_efficiency.md` §1.1）
4. **損益分岐の余裕**：USD の N* = 5 は差 0.0159 USD で、A の T5 の 1 タスクで決まっている。秒の損益分岐は求まらない
5. **費用は単価からの計算**：請求額ではない。キャッシュの扱いは agy の実測に従う（会話をまたいだプレフィックスキャッシュは効かない。`v2_b_efficiency.md` §1.4）
6. **B の文脈の伸び**：B のプロンプトは T1 → T5 で約 1.1 万字伸びる（§2.6）。B も O(1) の文脈にはなっていない
7. **ゲームの側**：falling-blocks の base は全走行で同じ `87bdfdaf`。T1〜T5 は v1 の要求から作った同じ 5 タスク
